객체는 왜 감자 주문서가 되었나

관련된 값을 객체 하나로 묶고, 속성 이름으로 필요한 값을 꺼냅니다.

세 장짜리 주문은 자꾸 한 장을 잃어버립니다

감자튀김 메뉴, 3번 테이블, 맵지 않음. 모두 같은 주문인데 값이 따로 흩어져 있으면 함께 챙겨야 한다는 사실이 코드에 드러나지 않습니다.

const menu = '감자튀김'
const table = 3
const spicy = false

한 주문에 딸린 값이라면 객체(object) 하나로 묶을 수 있습니다.

const order = {
  menu: '감자튀김',
  table: 3,
  spicy: false,
}

serve(order)

이제 order 하나가 주문 전체를 가리킵니다. 함수를 호출할 때도 종이 세 장을 따로 건네지 않고 주문서 한 장을 건네면 됩니다.

객체는 이름표와 값을 한 묶음으로 보관합니다

객체는 서로 관련된 값을 이름표와 함께 한 묶음으로 보관하는 데이터입니다.

const order = {
  menu: '감자튀김',
  table: 3,
  spicy: false,
}
  • menu, table, spicy는 각 칸의 이름, 즉 키(key) 입니다.
  • '감자튀김', 3, false는 각 키에 연결된 값(value) 입니다.
  • 키와 값 한 쌍을 객체의 속성(property) 이라고 부릅니다.
  • { ... }로 객체를 만드는 이 문법은 객체 리터럴입니다.

점 뒤에 칸 이름을 쓰면 값이 나옵니다

주문서에서 테이블 칸만 읽고 싶다면 다음처럼 씁니다.

order.table // 3
order.menu // '감자튀김'

이것을 점 표기법이라고 합니다. 점 뒤의 table은 꺼낼 속성의 이름이고, 표현식의 결과는 그 칸에 들어 있던 값 3입니다.

감자 식당 글에서 이미 본 orderState.status도 같은 방식입니다.

const orderState = {
  status: '주문 전',
  order: null,
}

orderState.status // '주문 전'

배열은 순서, 객체는 이름으로 찾습니다

const orderArray = ['감자튀김', 3, false]
const orderObject = { menu: '감자튀김', table: 3, spicy: false }

배열도 여러 값을 담지만 순서로 찾습니다. 객체는 이름으로 찾습니다. orderArray[1]의 3은 위치의 뜻을 기억해야 하지만, orderObject.table은 이름만 보고 테이블 번호라는 뜻을 알 수 있습니다.

둘 중 하나가 항상 더 좋은 것은 아닙니다. 순서가 중요한 목록은 배열, 같은 대상에 딸린 값을 이름으로 구분할 때는 객체가 잘 맞습니다.

감자 주문서 비유가 맞는 곳과 깨지는 곳

  • 주문서 한 장에 관련 정보를 모은다는 점은 객체와 잘 맞습니다.
  • 현실 주문서는 칸이 고정돼 있을 수 있지만, JavaScript 객체의 속성은 나중에 추가하거나 바꿀 수도 있습니다.
  • 객체는 현실의 물건만 나타내지 않습니다. 화면 상태나 설정처럼 관련된 값의 묶음도 객체가 될 수 있습니다.
  • 객체의 값에는 글자와 숫자뿐 아니라 다른 객체나 함수도 들어갈 수 있습니다.

나중에 만날 구조 분해 할당, 스프레드, 옵셔널 체이닝은 모두 객체의 칸을 다루는 다음 단계입니다. 이번에는 묶고, 이름으로 꺼낸다까지만 가져갑니다.
