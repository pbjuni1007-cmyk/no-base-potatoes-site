중심 질문: “값이 없음”과 0은 왜 구분해야 할까요?

프로그램은 값이 정해지지 않은 상태와 값이 정해졌는데 그 결과가 0, false, 빈 문자열인 상태를 구분해야 합니다. 앞의 조건 글에서 모두 거짓처럼 취급될 수 있다고 배웠지만, 조건에서의 취급과 값의 뜻은 같은 문제가 아닙니다.

JavaScript에서 null은 “값이 없음을 나타내려고 개발자가 넣는 값”으로 흔히 사용하고, undefined는 값이 아직 주어지지 않았을 때 나타나는 값입니다. 반면 0, false, ''는 각각 숫자, 불리언, 문자열 타입의 실제 값입니다.

const selectedOrder = null
let customerName
const stockCount = 0
const isTakeout = false
const note = ''

각 줄을 실행한 뒤 이름과 값은 다음처럼 연결됩니다.

옆으로 밀어서 비교 →
값이 주문에서 뜻하는 것
null선택된 주문이 없다고 코드가 직접 표시함
undefinedcustomerName의 값이 아직 정해지지 않음
0현재 감자 재고가 0개임
false포장 주문이 아님
''메모가 빈 문자열임

0, false, 빈 문자열은 조건문에서 거짓처럼 취급되는 falsy 값입니다. 그렇다고 항상 “없는 값”은 아닙니다. 재고 0과 포장 아님은 유효한 정보일 수 있습니다.

console.log(selectedOrder) // null
console.log(customerName) // undefined
console.log(stockCount) // 0
console.log(isTakeout) // false
console.log(note === '') // true

마지막 줄은 note가 빈 문자열인지를 확인해 true를 출력합니다. 출력이 비슷해 보여도 다섯 값이 하나로 합쳐진 것은 아닙니다.

??는 null과 undefined만 대신합니다

Nullish 병합 연산자 ??는 왼쪽 값이 null 또는 undefined일 때만 오른쪽 기본값을 사용합니다.

const ordered = 0
const unknown = undefined

console.log(ordered ?? 1)
console.log(unknown ?? 1)
// 0
// 1
  1. ordered에는 숫자 0이 있으므로 ??는 그대로 0을 돌려줍니다.
  2. unknown은 undefined이므로 ??는 오른쪽 기본값 1을 돌려줍니다.

재고 0을 기본값 1로 덮어쓰지 않는 것이 핵심입니다. ||는 0, false, 빈 문자열도 거짓처럼 보고 오른쪽 값을 고르므로 같은 역할이 아닙니다. 이 글에서는 ||의 전체 규칙보다 0을 다루는 결과 차이만 봅니다.

0 || 1 // 1
0 ?? 1 // 0

Python의 None은 Python의 값입니다

Python에서 None은 “값이 없음”을 나타내는 하나뿐인 값입니다. JavaScript의 null이나 undefined와 쓰이는 장면이 비슷할 수 있지만, 서로 다른 언어의 값이므로 같다고 부르지 않습니다.

selected_order = None

if selected_order is None:
    print('주문 선택 전')

예상 출력은 다음과 같습니다.

주문 선택 전
  1. selected_order라는 이름에 None을 직접 넣습니다.
  2. is None으로 그 값이 None인지 확인합니다.
  3. 조건이 참이므로 안내 문장을 출력합니다.

Python에는 JavaScript의 undefined에 직접 대응하는 값이 없습니다. 값을 할당하지 않은 이름을 읽으면 “아직 undefined다”가 아니라 NameError가 발생합니다. NameError 는 Python이 사용한 이름을 찾지 못했다는 오류입니다.

print(customer_name)
# NameError: name 'customer_name' is not defined

또 Python의 value or default도 JavaScript의 ??와 같지 않습니다. or는 0도 거짓으로 판단해 기본값으로 바꾸기 때문입니다.

stock_count = 0
print(stock_count or 1)
# 1

빈 주문칸 비유가 맞는 곳과 깨지는 곳

주문서 자체가 없거나, 칸이 아직 비었거나, 재고에 0이 적힌 장면은 값을 구분하는 데 도움이 됩니다.

하지만 JavaScript가 null을 보면 “일부러 비웠다”는 사람의 의도까지 검증해 주지는 않습니다. 이는 개발자가 그렇게 사용하기로 한 표현입니다. 또 undefined가 나오는 상황도 선언 뒤 값이 없을 때뿐 아니라 없는 속성을 읽는 경우 등 여러 가지입니다.

Python의 None도 현실 주문서의 빈칸 자체가 아닙니다. 코드에서 상태를 표현하는 Python 값이며, JavaScript의 두 값을 하나로 합친 이름도 아닙니다.
