“없음”처럼 보여도 같은 값은 아닙니다

앞의 조건 글에서는 조건 자리의 일부 값이 거짓처럼 취급된다고 배웠습니다. 이제 거짓처럼 취급된다는 이유만으로 서로 다른 값을 모두 “없음”으로 묶으면 안 되는 이유를 봅니다.

const selectedOrder = null
let customerName
const stockCount = 0
const isTakeout = false
const note = ''

이 값들은 서로 다른 상태를 표현합니다.

옆으로 밀어서 비교 →
값이 주문에서 뜻하는 것
null선택된 주문이 없다고 코드가 직접 표시함
undefinedcustomerName의 값이 아직 정해지지 않음
0현재 감자 재고가 0개임
false포장 주문이 아님
''메모가 빈 문자열임

0, false, 빈 문자열은 조건문에서 거짓처럼 취급되는 falsy 값입니다. 그렇다고 항상 “없는 값”은 아닙니다. 재고 0과 포장 아님은 유효한 정보일 수 있습니다.

??는 null과 undefined만 대신합니다

Nullish 병합 연산자 ??는 왼쪽 값이 null 또는 undefined일 때만 오른쪽 기본값을 사용합니다.

const ordered = 0
const unknown = undefined

ordered ?? 1 // 0
unknown ?? 1 // 1

재고 0을 기본값 1로 덮어쓰지 않는 것이 핵심입니다. ||는 0, false, 빈 문자열도 거짓처럼 보고 오른쪽 값을 고르므로 같은 역할이 아닙니다. 이 글에서는 ||의 전체 규칙보다 0을 다루는 결과 차이만 봅니다.

0 || 1 // 1
0 ?? 1 // 0

Q2 · 대체할 두 값 찾기

??가 오른쪽 기본값을 사용하는 조건을 완성해 봅시다.

??는 왼쪽이 또는 일 때만 오른쪽 값을 사용합니다.

빈 주문칸 비유가 맞는 곳과 깨지는 곳

주문서 자체가 없거나, 칸이 아직 비었거나, 재고에 0이 적힌 장면은 값을 구분하는 데 도움이 됩니다.

하지만 JavaScript가 null을 보면 “일부러 비웠다”는 사람의 의도까지 검증해 주지는 않습니다. 이는 개발자가 그렇게 사용하기로 한 표현입니다. 또 undefined가 나오는 상황도 선언 뒤 값이 없을 때뿐 아니라 없는 속성을 읽는 경우 등 여러 가지입니다.
