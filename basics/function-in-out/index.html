중심 질문: 함수는 언제 실행되고 무엇을 돌려줄까요?

함수(function) 는 필요할 때 호출할 수 있도록 하나로 묶은 코드입니다. 함수는 이름이 있을 수도, 없을 수도 있습니다. 이 글에서는 이름이 cook인 함수를 사용합니다. 함수를 적어 두는 정의와 실제로 실행시키는 호출은 다릅니다.

  • 매개변수(parameter) 는 함수를 정의할 때 적는 입력 이름입니다.
  • 인수(argument) 는 함수를 호출할 때 넣는 실제 값입니다.
  • return은 함수 실행을 끝내고 호출한 곳에 값을 돌려줍니다.
  • 반환값은 호출한 곳이 돌려받은 값입니다.

감자 식당의 조리법을 적어 둔 것만으로 조리가 시작되지는 않습니다. 주문을 넣어 조리 함수를 호출해야 본문이 실행됩니다.

기존 JavaScript에서는 어떻게 썼을까요?

function cook(menu, quantity) {
  return `${menu} ${quantity}개 완성`
}

const result = cook('감자튀김', 2)
console.log(result)

백틱으로 감싼 문자열의 ${menu}는 menu 값을 문장 안에 넣는 표시입니다.

  1. function cook(...)은 함수를 정의합니다. 이때 조리는 아직 실행되지 않습니다.
  2. 정의에 적은 menu, quantity는 매개변수입니다.
  3. cook('감자튀김', 2)가 함수를 호출합니다. '감자튀김', 2는 인수입니다.
  4. return이 만든 문자열이 result에 들어갑니다.
  5. 예상 출력은 감자튀김 2개 완성입니다.

같은 상황을 Python으로 쓰면 어떻게 될까요?

def cook(menu, quantity):
    return f'{menu} {quantity}개 완성'

result = cook('감자튀김', 2)
print(result)

def는 Python에서 함수를 정의할 때 쓰는 키워드입니다. f'...' 문자열 안의 {menu}는 변수 값을 문장에 넣는 표시입니다.

  1. def cook(...):은 함수를 정의합니다.
  2. menu, quantity는 매개변수입니다.
  3. '감자튀김', 2를 인수로 넣어 cook을 호출합니다.
  4. return이 같은 결과 문자열을 호출한 곳으로 돌려줍니다.
  5. 예상 출력은 JavaScript와 같은 감자튀김 2개 완성입니다.

두 언어의 실제 차이

정의에 쓰는 문법은 다릅니다. JavaScript는 function과 중괄호를, Python은 def, 콜론과 들여쓰기를 사용합니다. 하지만 이 예제의 흐름은 같습니다.

정의 → 인수를 넣어 호출 → 매개변수가 값을 받음 → return → 반환값

return을 생략하거나 돌려줄 값 없이 사용하면 두 언어 모두 “의미 있는 값을 지정하지 않은 반환 결과”를 만듭니다. 그 값의 이름은 다릅니다.

function finishOrder() {}
console.log(finishOrder()) // undefined
def finish_order():
    return

print(finish_order())  # None

JavaScript는 undefined, Python은 None을 출력합니다.

흔한 오해 경계

  • 함수 정의는 실행 예약표가 아닙니다. 호출해야 함수 본문이 실행됩니다.
  • 매개변수는 정의에 적은 이름이고, 인수는 호출에 넣은 실제 값입니다.
  • console.log()나 print()로 화면에 보여 주는 일과 return으로 값을 호출한 곳에 돌려주는 일은 다릅니다.

조리 기계 비유는 인수 → 실행 → 반환값 흐름을 기억하는 데 도움이 됩니다. 하지만 함수는 실제 기계가 아니며 입력이나 의미 있는 반환값이 없는 함수도 있습니다.
