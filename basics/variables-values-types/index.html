변수·값·타입

변수는 감자 통인가, 이름표인가

변수 이름, 저장된 값과 값의 타입을 구분하고 const와 let이 무엇을 막는지 확인합니다.

이름, 값, 타입은 같은 것이 아닙니다

const menu = '감자튀김'
let quantity = 2
  • menu, quantity는 값을 다시 찾기 위한 변수 이름입니다.
  • '감자튀김', 2는 코드가 실제로 다루는 값입니다.
  • 문자열과 숫자는 값의 타입, 즉 종류입니다.

이처럼 =로 변수 이름에 값을 연결하는 일을 할당이라고 합니다.

typeof로 값의 타입을 확인할 수 있습니다.

typeof menu // 'string'
typeof quantity // 'number'

JavaScript에서는 변수 이름에 타입을 적지 않습니다. let으로 만든 변수에는 나중에 다른 타입의 값을 다시 넣을 수도 있습니다. 할 수 있다는 뜻이지, 읽기 좋은 코드라는 뜻은 아닙니다.

const와 let은 다시 할당하는 규칙이 다릅니다

const menu = '감자튀김'
let quantity = 2

quantity = 3 // 가능
menu = '감자전' // 오류: const 이름에 다른 값을 재할당함

let은 같은 이름에 새 값을 재할당할 수 있습니다. const는 선언할 때 값을 함께 정해야 하고, 그 이름에 다른 값을 재할당할 수 없습니다.

여기까지의 중심은 이름·값·타입을 나누고, 같은 이름에 다른 값을 다시 할당할 수 있는지 구분하는 것입니다.

보조 사례: const 객체의 속성은 바꿀 수 있습니다

별도 객체 글에서 더 자세히 배울 내용입니다. 지금은 const가 값의 내부까지 얼리지는 않는다는 경계만 확인합니다.

const order = { menu: '감자튀김' }

order.menu = '감자전' // 가능: 같은 객체의 menu 속성을 바꿈
order = { menu: '웨지감자' } // 오류: order에 다른 객체를 재할당함

order.menu는 바꿀 수 있지만, order라는 이름에 다른 객체를 다시 할당할 수는 없습니다.

스스로 확인

Q1 · 이름·값·타입 구분하기

아래 코드의 이름·값·타입을 바르게 연결한 것은 무엇일까요?

const menu = '감자튀김'
세 역할을 바르게 연결한 답을 고르세요.

Q2 · const 경계 연결하기

const가 막는 일과 막지 않는 일을 구분해 봅시다.

const는 같은 변수 이름에 다른 값을 하는 일을 막지만, 객체의 변경까지 자동으로 막지는 않습니다.

재료통 비유가 맞는 곳과 깨지는 곳

재료통의 이름표는 변수 이름, 내용물은 값, 감자·소스 같은 종류는 타입을 떠올리는 데 도움이 됩니다.

하지만 실제 변수는 물리적인 통이 아닙니다. 특히 const 객체를 “자물쇠로 잠근 통”이라고 생각하면 속성도 못 바꾼다고 오해합니다. const가 막는 것은 이름에 다른 값을 다시 할당하는 일입니다.
