01새 폴더에서 준비하기

개인 Mac의 기존 터미널과 편집기, Python 3.11 이상을 사용합니다. 버전은 수업 환경 기준이지 아래 문법의 최소 버전이라는 뜻은 아닙니다. 패키지 설치·로그인·외부 통신은 없습니다. 학습용 자격 증명도 필요 없으며 실제 자격 증명은 입력하지 않습니다.

02한 건과 여러 건 구분하기

{}로 묶인 딕셔너리는 거래 한 건입니다. "amount" 같은 이름인 키로 800 같은 값을 찾습니다. 바깥 []는 거래 여러 건을 순서대로 담는 리스트입니다. =는 오른쪽 값을 왼쪽 이름에 연결하는 대입이며, 같은지 묻는 비교가 아닙니다.

빈 파일에 입력하세요. sales[0]은 첫 거래입니다. 위치 번호는 0부터 시작합니다. 첫 출력과 반복 출력이 각각 무엇일지 예상해 보세요.

sales = [
    {"region": "서울", "amount": 800},
    {"region": "부산", "amount": 1000},
    {"region": "서울", "amount": 1500},
]

print(sales[0]["amount"])
for sale in sales:
    print(sale["amount"])

for는 한 건씩 꺼내 이번 차례의 sale에 연결합니다. : 뒤 네 칸 들여쓴 줄이 매번 실행됩니다. 첫 print는 반복 밖이어서 한 번만 실행됩니다.

python3 review_sales.py

정상 출력은 다음과 같습니다. 첫 거래를 따로 출력한 뒤 전체를 돌기 때문에 800이 두 번 보입니다.

800
800
1000
1500

작은 변형: 첫 print(sales[0]["amount"])의 키만 "region"으로 바꿔 저장·재실행하세요. 반복문과 데이터는 유지합니다. 첫 줄만 어떻게 바뀔까요?

완료 예시

  2. 첫 조회 키만 바꾸니 서울, 800, 1000, 1500이 나왔습니다.
  3. 리스트는 여러 거래를 담고, 딕셔너리는 한 거래에서 이름으로 값을 찾게 합니다.

03조건으로 금액 고르기

파일 전체를 다음 코드로 교체합니다. 이전 출력 코드를 남기지 마세요. selected = []는 빈 결과 목록입니다. >=는 '크거나 같다'라는 비교이고, if는 조건이 참일 때만 안쪽 줄을 실행합니다. append는 목록 끝에 값 하나를 붙입니다.

sales = [
    {"region": "서울", "amount": 800},
    {"region": "부산", "amount": 1000},
    {"region": "서울", "amount": 1500},
]

selected = []
for sale in sales:
    if sale["amount"] >= 1000:
        selected.append(sale["amount"])
print(selected)

if는 반복 안에서 매 거래를 검사합니다. append는 조건 안에도 있으므로 여덟 칸 들여씁니다. 마지막 출력은 반복 밖이어서 목록이 완성된 뒤 한 번 실행됩니다. 어떤 금액이 남을지 먼저 예상하세요.

python3 review_sales.py

정상 출력:

[1000, 1500]

작은 변형: >=만 >로 바꿔 저장·재실행합니다. 어떤 한 건이 빠지며, 왜 그럴까요?

완료 예시
  1. >= 1000에서는 [1000, 1500]이었습니다.
  2. > 1000에서는 [1500]이었습니다.
  3. 1000은 기준과 같아 '이상'에는 들어가지만 '초과'에는 들어가지 않습니다. 데이터가 아니라 조건의 경계가 바뀌었습니다.

04함수가 돌려준 합계 사용하기

파일 전체를 아래 코드로 교체합니다. 앞에서 바꾼 >는 >=로 복원합니다.

def는 함수 정의입니다. 정의만으로 계산되지는 않으며, total_sales(sales, 1000)처럼 호출하면 본문이 실행됩니다. records, minimum은 입력받을 이름인 매개변수이고, 호출할 때 건네는 sales, 1000은 인수입니다.

sales = [
    {"region": "서울", "amount": 800},
    {"region": "부산", "amount": 1000},
    {"region": "서울", "amount": 1500},
]

def total_sales(records, minimum):
    total = 0
    for sale in records:
        if sale["amount"] >= minimum:
            total = total + sale["amount"]
    return total

result = total_sales(sales, 1000)
print(result)
print(result + 500)

total은 지금까지의 합계이며 아직 더한 값이 없어 0부터 시작합니다. total = total + ...는 이전 합계에 이번 금액을 더해 갱신합니다. 800은 건너뛰므로 0 → 1000 → 2500이 됩니다.

return total은 반복 밖, 함수 안에 있습니다. 모두 더한 후 호출한 곳으로 합계를 돌려줍니다. 반복 안에 넣으면 첫 반복 중 함수를 끝낼 수 있습니다.

result에 반환된 숫자를 저장하고 print로 화면에 보여 줍니다. result + 500은 그 숫자로 새 계산이 가능한지 확인하는 줄입니다. 원래 판매 기록이나 result를 수정하지 않습니다.

함수가 값을 return하지 않고 끝나면 호출한 곳에는 None이 돌아옵니다. None은 값이 없음을 나타내는 특별한 값이며, 숫자 0이 아닙니다. 함수 안에서 print(total)로 숫자를 보여 줘도 그 숫자가 반환되는 것은 아닙니다. 따라서 반환값이 None인 상태에서 500을 더하면 TypeError(서로 맞지 않는 종류의 값으로 연산했다는 오류)가 납니다.

python3 review_sales.py

정상 출력:

2500
3000

작은 변형: 호출의 인수만 total_sales(sales, 1500)으로 바꾸세요. 함수 본문과 두 출력 줄은 유지합니다. 두 결과는 어떻게 바뀌며, 같은 함수가 다른 기준을 계산할 수 있는 이유는 무엇인가요?

완료 예시
  1. 기준 1000에서는 2500, 3000이 나왔습니다.
  2. 기준 1500에서는 1500, 2000이 나왔습니다.
  3. 전달한 기준이 minimum이 됩니다. return이 돌려준 숫자를 저장했기에 출력과 이후 계산에 재사용할 수 있었습니다. 화면에 보여 주는 것과 값을 반환하는 것은 다릅니다.

결과가 다르다면

저장 여부와 실행 폴더를 먼저 확인하세요. 오류에 표시된 파일명·줄 번호와 마지막 설명을 읽고, 해당 줄 주변의 들여쓰기와 "amount" 철자를 대조합니다. 해결되지 않으면 멈추고 오류 메시지와 코드를 함께 질문하세요.
