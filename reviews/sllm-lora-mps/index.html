수업에서는 모델을 불러오고, 데이터를 학습시키고, 점수를 출력했습니다. 그런데 어댑터 파일이 생겼다는 것과 모델이 정확히 답한다는 것은 같은 말일까요? 이번에는 명령을 끝내는 데서 한 걸음 더 가 봅니다.

제공된 HR 규정 중 두 주제로 작은 학습을 합니다. 같은 모델에서 LoRA를 끈 답변과 켠 답변을 비교하고 질문의 표현 하나만 바꿉니다. 끝났을 때 무엇이 바뀌었고, 이 결과만으로는 무엇을 알 수 없는지 설명하는 것이 목표입니다.

정상 결과와 완료 예시는 비교 기준이지 여러분의 실행 완료 증명서가 아닙니다. 표시된 60분은 예상치이며 설치·다운로드·Mac별 학습 대기 시간을 보장하지 않습니다.

01기존 실습을 지키고 시작하기

대상은 Apple Silicon Mac, 터미널, Python 3.11과 교수님 실습용 Python 환경입니다. MPS는 PyTorch가 Mac GPU를 사용하는 실행 장치입니다. 이번 코드의 MPS 학습은 FP32 LoRA이며 CUDA용 4비트 QLoRA로 바꾸지 않습니다.

수업 때 시작한 학습·평가가 실행 중이면 끝난 뒤 시작하세요. 서버·컨테이너를 만들지 않아 포트는 열지 않습니다. 계정과 학습용 자격 증명도 필요하지 않으며 실제 자격 증명·토큰·회사 비밀자료는 입력하지 않습니다.

새 임시 폴더를 만들고 이 터미널을 마지막까지 유지합니다.

NBP_REVIEW_ROOT="$(mktemp -d /tmp/nbp-sllm-review.XXXXXX)"
cd "$NBP_REVIEW_ROOT"
pwd

정상 출력은 /tmp/nbp-sllm-review. 또는 /private/tmp/nbp-sllm-review.로 시작하는 새 경로입니다. 다른 위치거나 생성 오류가 있으면 멈춥니다.

Finder로 제공받은 실습본의 scripts, dataset, requirements.txt만 복사해 지금 폴더에 넣으세요. 원본을 이동하거나 별칭으로 연결하지 않습니다. 예전 결과와 섞이지 않도록 models와 outputs는 복사하지 않습니다.

NBP_PYTHON에는 수업용 가상환경의 bin/python 절대 경로를, NBP_MODEL_CACHE에는 이미 받은 모델이 있는 Hugging Face hub 폴더의 절대 경로를 저장합니다. Finder에서 확인하고 NBP_PYTHON="확인한 경로"처럼 입력하세요. 다른 사람의 사용자명을 그대로 복사하지 않습니다. 환경이나 캐시가 없으면 여기서 멈추고 준비 도움을 받습니다. 새 설치·약 3.1GB 모델 다운로드는 자동 수행하지 않습니다.

"$NBP_PYTHON" -B -c "import sys, torch; print(sys.executable); print(torch.__version__); print('MPS:', torch.backends.mps.is_available())"

정상 결과는 선택한 수업용 Python 경로와 MPS: True입니다. False나 import 오류면 학습으로 넘어가지 않습니다. requirements.txt와 환경 버전이 다르면 확인하고, 기존 환경을 무작정 업그레이드하지 마세요.

모델 캐시는 재사용하고 새 데이터 캐시는 이 폴더에 둡니다. 다음 설정은 다운로드를 막습니다. 캐시가 없으면 실패해야 합니다.

export HF_HUB_CACHE="$NBP_MODEL_CACHE" HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 HF_HUB_DISABLE_TELEMETRY=1 HF_DATASETS_CACHE="$NBP_REVIEW_ROOT/datasets-cache" TOKENIZERS_PARALLELISM=false

정상일 때 출력이 없습니다. 아래 코드는 패키지를 자동 설치하지 않습니다.

완료 예시

새 폴더에 scripts·dataset의 실제 복사본이 있고 models·outputs는 아직 없습니다. 수업용 Python이 MPS를 사용할 수 있으며 모델은 이미 받은 캐시만 이용합니다. 기존 실습 폴더는 그대로 남아 있습니다.

02모델에게 줄 답과 나중에 물을 질문 나누기

SFT는 질문과 바람직한 답변의 예를 이용한 추가 학습입니다. messages 안의 system은 역할·지시, user는 질문, assistant는 학습할 답입니다. 이번 CLM은 앞의 토큰을 보고 다음 토큰을 예측합니다. 학습 때는 정답을 보여주지만 평가 때는 정답을 입력에 넣지 않습니다.

  • train: 가중치를 바꾸는 연습 문제입니다.
  • validation: 학습 중 상태를 비교하고 저장할 어댑터를 고르므로 선택에 이미 영향을 줍니다.
  • evaluation: 학습 후 두 모델을 비교하는 질문입니다. 점수를 올리려고 이 질문·정답을 train에 넣지 않습니다.

연습장·중간 점검·마지막 점검으로 생각하면 쉽습니다. 다만 같은 HR 규정이 세 묶음에 걸쳐 등장합니다. 새 규정을 알아냈는지 보는 시험이 아니라, 본 규정에 관한 다른 질문에 답하는 작은 실험입니다. 파일 이름이 다르다고 내용까지 독립인 것은 아닙니다.

예상해 보세요. 평가 정답까지 train에 복사하면 점수는 좋아질 수 있어도 무엇을 주장하기 어려워질까요?

이번에 고른 두 주제는 고유 정책의 우선순위와 금지되는 답변 방식입니다. 예를 들어 “회사 고유 정책과 일반 관행 중 무엇을 우선하나요?”라는 질문에는 회사 고유 정책이 일반 관행보다 우선한다는 규정을 확인해야 합니다. 법령·보안 규정·고객 계약 등 더 앞선 기준도 있으므로 “회사 정책이 언제나 최우선”은 아닙니다.

아래 코드를 새 폴더의 review_data.py로 저장합니다. 준비 코드의 내부를 해석하거나 변형하는 것은 이번 과제가 아닙니다. 실행 후 12/2건과 정답 토큰이 남는지만 확인하고, 질문·답변을 읽는 활동으로 넘어갑니다. 교수님 학습 코드를 대체하지 않고 범위를 작게 고르는 코드이며 기존 파일이 있으면 덮어쓰지 않습니다.

import json
from pathlib import Path
from transformers import AutoTokenizer
from trl.chat_template_utils import get_training_chat_template

root = Path(__file__).resolve().parent
assert not (root / "models").exists(), "기존 모델이 없는 새 복사본에서 시작하세요."
assert not (root / "outputs").exists(), "기존 결과가 없는 새 복사본에서 시작하세요."
sections = {"section-081", "section-094"}

def read(path):
    return [json.loads(line) for line in path.read_text().splitlines() if line.strip()]

train = [r for r in read(root / "dataset/training/hr_sft_train.jsonl")
         if r.get("source_section_id") in sections]
valid = [r for r in read(root / "dataset/training/hr_sft_validation.jsonl")
         if r.get("source_section_id") in sections]
assert (len(train), len(valid)) == (12, 2), "실습본 버전을 확인하세요."
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-1.5B-Instruct", local_files_only=True)
template = get_training_chat_template(tokenizer)
for row in train + valid:
    encoded = tokenizer.apply_chat_template(
        row["messages"], chat_template=template, tokenize=True,
        return_dict=True, return_assistant_tokens_mask=True,
    )
    count = len(encoded["input_ids"])
    targets = sum(encoded["assistant_masks"])
    print(row["id"], "전체 토큰", count, "정답 토큰", targets)
    assert count <= 384 and targets > 0, "잘림 또는 정답 마스크를 확인하세요."

evaluation = read(root / "dataset/evaluation/hr_eval.jsonl")
chosen = [r for r in evaluation if r["id"] in {"eval-004", "eval-009"}]
assert len(chosen) == 2
original = next(r for r in chosen if r["id"] == "eval-009")
variant = dict(original)
variant["id"] = "review-paraphrase-009"
variant["question"] = "Human AI Corporation의 고유 정책은 일반적인 회사 관행과 충돌할 때 무엇을 우선하나요? 적용 기준과 예외를 설명해 주세요."

def write_new(path, rows):
    with path.open("x", encoding="utf-8") as stream:
        for row in rows:
            stream.write(json.dumps(row, ensure_ascii=False) + "\n")

write_new(root / "review-train.jsonl", train)
write_new(root / "review-validation.jsonl", valid)
evaluation_path = root / "dataset/evaluation/hr_eval.jsonl"
backup = evaluation_path.with_name("hr_eval.original.jsonl")
assert not backup.exists()
evaluation_path.rename(backup)
write_new(evaluation_path, chosen + [variant])
print("학습 12 / 검증 2 / 평가 2 + 표현 변형 1")
"$NBP_PYTHON" -B review_data.py

정상이라면 14건 모두 전체 토큰 수가 384 이하이고 정답 토큰 수는 양수입니다. 마지막에 학습 12 / 검증 2 / 평가 2 + 표현 변형 1이 나옵니다. 오류나 일부 파일만 만들어진 상태라면 재실행으로 덮어쓰지 말고 확인합니다. 검사 조건을 지우지 마세요.

assistant_only_loss=True는 질문·지시를 읽되 assistant 답변 토큰을 손실 계산 대상으로 삼는다는 뜻입니다. 정답 마스크는 그 위치를 표시합니다. 준비 코드는 이번 설치 버전의 TRL이 고르는 학습용 대화 템플릿으로 확인합니다. 일반 추론용 템플릿과 같다고 가정하지 않습니다.

편집기로 review-train.jsonl과 review-validation.jsonl의 첫 항목에서 질문·답변을 읽으세요. 평가 파일을 train에 합치지 않습니다. 별도 데이터 변형 학습은 추가하지 않고 마지막 단계의 질문 표현 변형으로 이어갑니다.

완료 예시

train은 답을 배우고 validation은 학습 중 모델 선택에 쓰며 evaluation은 이후 비교에 사용됩니다. 평가 답을 학습하면 시험 문제를 미리 연습한 셈이므로 새 질문에 대한 능력을 과장할 수 있습니다. 정답 토큰이 0이면 의도한 답변 학습을 확인한 것이 아닙니다.

03작은 학습을 하고 남은 파일 읽기

파라미터는 모델의 계산에 쓰이는 수치입니다. LoRA는 기존 모델의 가중치를 고정하고 작은 추가 가중치인 어댑터를 학습합니다. 문서를 검색하는 RAG와 달리 학습 예를 통해 수치를 바꿉니다. 어댑터를 붙인다고 개인정보 보호나 정답이 보장되지는 않습니다.

두 규정의 학습 12건을 한 번만 봅니다. epoch=1은 선택한 데이터 한 바퀴, 384는 최대 입력 토큰 길이입니다. 답변이 개선되지 않아도 실험 실패라고 단정하지 않습니다. 원래 전체 데이터 학습의 성능을 재현하는 실험도 아닙니다.

예상해 보세요. 아래 명령은 기존 Qwen 파일 전체를 바꿀까요, 학습한 어댑터를 따로 저장할까요?

SFT_MAX_LENGTH=384 SFT_EPOCHS=1 SFT_LEARNING_RATE=1e-4 SFT_GRAD_ACCUM=8 "$NBP_PYTHON" -B scripts/train_lora.py --train review-train.jsonl --validation review-validation.jsonl

정상 시작 출력은 Device: mps, Mode: FP32 LoRA Apple MPS, 길이 384, Epoch 1, 데이터 12/2입니다. 공백은 다를 수 있습니다. CPU·다른 모델·다른 건수이면 Control+C로 중단하세요. nan, 메모리 부족 오류, 다른 앱 사용이 어려운 메모리 압박이 있어도 중단합니다. 메모리 안전 한도를 해제하거나 같은 폴더에서 반복 실행하지 않습니다.

학습이 끝나 터미널 프롬프트가 돌아온 뒤 확인합니다. 소요 시간은 Mac 상태에 따라 달라집니다.

ls models/hr-qwen-lora

정상 저장에는 adapter_config.json, adapter_model.safetensors가 포함됩니다. 어댑터가 어떤 위치에 추가됐는지 설정을 읽어 봅니다.

"$NBP_PYTHON" -B -m json.tool models/hr-qwen-lora/adapter_config.json

정상 기준은 peft_type: LORA, r: 16, bias: none과 target_modules의 q_proj·k_proj·v_proj·o_proj·gate_proj·up_proj·down_proj입니다. 목록 순서는 달라도 됩니다. target_modules는 추가 가중치를 붙인 층의 이름이고 r은 추가 행렬의 크기를 정하는 설정입니다. 이름을 외우기보다 모델 전체를 새로 학습하는 대신 지정한 층에 추가 가중치를 두었다는 관계를 읽으세요. 설정 확인은 모든 파라미터의 실제 변경 여부를 검사한 것과 다릅니다. 폴더 존재만으로 완료를 판단하지 않고 실행 요약도 읽습니다.

"$NBP_PYTHON" -B -m json.tool outputs/training_summary.json

정상 기준은 모델 Qwen/Qwen2.5-1.5B-Instruct, 장치 mps, 한 epoch, 유한한 final_train_loss와 양수인 global_step입니다. loss의 정답 숫자는 없습니다. 이번 12건·누적 8은 갱신이 2회 정도라 중간 로그가 없을 수 있습니다. 최종 loss 하나만 보고 “꾸준히 감소했다”고 하지 않습니다.

loss는 학습 대상 토큰을 얼마나 잘 예측했는지 계산한 오차이지 회사 규정 정답률이 아닙니다. 그것은 다음 단계에서 답변과 근거를 읽으며 확인합니다. 설정 변경·재학습 과제는 추가하지 않고 저장 결과를 관찰합니다.

완료 예시

기본 모델은 그대로이고 새 폴더에 어댑터와 요약이 남습니다. global_step은 수치 갱신 횟수, loss는 토큰 예측 오차입니다. 이 둘만으로 HR 규정을 정확히 답한다고 결론 내릴 수 없습니다. 실제 저장·요약을 확인하지 못했으면 미검증입니다.

04같은 질문, 다른 표현, 실제 답변

교수님 평가 코드는 같은 모델에서 disable_adapter()로 LoRA를 끈 답변을 만들고 다시 켠 답변을 만듭니다. 여기서 Base는 Instruct 모델에 이번 HR 어댑터를 적용하지 않은 상태이지 아무 학습도 안 한 모델이 아닙니다. 두 분기는 동일 질문·동일 생성 조건입니다. 이 실습본의 MPS 학습은 FP32, 평가는 FP16이므로 기록에서도 구분합니다.

예상해 보세요. LoRA 답변이 더 길어졌다면 무조건 더 정확해진 것일까요?

작은 변형: eval-009의 질문을 “고유 정책은 일반적인 회사 관행과 충돌할 때 무엇을 우선하나요?”로 바꿨습니다. 준비 코드가 마지막 항목으로 추가했습니다. 같은 정책을 묻되 표현을 바꿉니다. 모델·규정·참고 정답을 유지했을 때 일관되게 답할지 예상하세요. 이 변형 점수는 원래 질문과 따로 읽습니다.

"$NBP_PYTHON" -B scripts/evaluate_model.py --max-evaluation 3

정상 시작 출력은 같은 Qwen, 이번 폴더의 어댑터, mps, 평가 3건입니다. 다르면 중단합니다. 완료 뒤 outputs/evaluation_results.jsonl과 outputs/evaluation_summary.json이 생깁니다. 점수 상승은 성공 조건이 아닙니다. 재실행은 기존 출력을 덮어쓰므로 먼저 결과를 다른 이름으로 보관해야 합니다.

"$NBP_PYTHON" -B -c "import json; from pathlib import Path; rows=[json.loads(x) for x in Path('outputs/evaluation_results.jsonl').read_text().splitlines()]; [(print('\nID:',r['id'],'\n질문:',r['question'],'\n근거:',r['reference_answer'],'\nBase:',r['base_answer'],'\nLoRA:',r['tuned_answer'])) for r in rows]"

정상이라면 질문 2개와 표현 변형 1개 각각에 근거·Base·LoRA 답변이 나옵니다. 생성 답변은 고정 문자열이 아닙니다. 비어 있거나 오류가 있으면 점수만 보고 넘어가지 않습니다.

  • 참고 규정의 조건·예외를 실제로 말했나요?
  • 근거에 없는 승인 절차·숫자를 덧붙이지 않았나요?
  • 원래 질문과 바꾼 질문에서 같은 정책을 유지했나요?

키워드 점수는 단어의 포함 여부, F1은 참고 답변과의 단어 겹침을 바탕으로 한 지표입니다. 단어를 포함해도 관계를 반대로 말할 수 있습니다. 세 질문에는 unknown_policy가 없으므로 환각 관련 0은 미평가이지 환각 없음이 아닙니다. 요약 평균에는 표현 변형까지 들어가므로 독립적인 세 문제의 성능으로 해석하지 않습니다. 질문 수도 작아 회사 전체 규정 성능으로 일반화하지 않습니다.

완료 예시

필요한 정책 용어가 늘었다는 것과 답변 전체가 정확하다는 것은 다릅니다. 실제 조건·예외까지 맞는지 읽어야 합니다. 두 표현에 일관되게 답해도 모든 질문에 강하다는 증거는 아닙니다. 개선 없음·악화·근거 없는 추가도 그대로 기록합니다. 예상 답변을 직접 출력해서 생성 결과를 대신하지 않습니다.

실제 파일럿의 eval-004를 예로 봅시다. 참고 규정은 회사 고유 코드를 임의로 변경하지 말라고 합니다. 그런데 LoRA 답변에는 **“회사의 고유 정보나 코드를 사용하지 않아야 합니다.”**가 나왔습니다. 임의 변경 금지와 사용 금지는 다릅니다. 자동 종합 점수는 Base 0.0073에서 LoRA 0.0359로 높아졌지만 이 문장은 규정에 맞지 않습니다. 숫자 상승만으로 정확해졌다고 말할 수 없는 이유입니다. 이는 이번 12건·1epoch 실행의 한 사례이며 여러분의 생성 문장이 같아야 하는 것은 아닙니다.

rm -f ./review_data.py

정상일 때 출력이 없습니다. 오류면 중단합니다.

ls
