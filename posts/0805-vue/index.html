지난 수업 복습

지난 시간에는 아이언 감자 연구소의 기상 관제판을 외부 기상망에 연결했습니다. Axios로 날씨를 요청하고, async·await로 응답을 기다렸습니다. 성공한 응답은 객체에 담고, 실패하면 catch에서 다른 화면을 보여줬습니다.

오늘은 연구소의 출동 준비입니다. 값이 아직 없어도 화면이 깨지지 않게 보여주고, 준비된 화면 부품으로 관제판을 마무리한 뒤, 다른 사람이 열 수 있는 파일로 만듭니다.

아이언 감자 연구소가 출동하려면, 준비된 화면 부품과 안전한 값 처리, 배포용 파일 준비를 누가 맡을까요?

Element Plus: 준비된 화면 부품을 가져온다

UI 라이브러리는 입력칸, 버튼과 알림처럼 자주 쓰는 화면 부품을 미리 만들어 둔 코드 묶음입니다. Element Plus는 Vue 자체가 아니라, 따로 설치해 사용하는 Vue용 UI 라이브러리입니다.

npm install element-plus

설치 뒤 앱 시작 파일에서 Element Plus와 CSS를 등록합니다.

import { createApp } from 'vue'
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'
import App from './App.vue'

createApp(App).use(ElementPlus).mount('#app')

createApp(App)은 Vue 앱을 만들고, .use(ElementPlus)는 화면 부품 플러그인을 등록하며, .mount('#app')는 앱을 실제 화면에서 시작합니다.

Modern JavaScript: 없는 값에서 멈추고 기본 문구를 고른다

const forecast = null
const cityText = forecast?.city ?? '예보 대기 중'

?.는 forecast가 null이므로 city에 들어가지 않고 undefined를 돌려줍니다. 이어서 ??가 오른쪽의 예보 대기 중을 고릅니다.

?.는 빈 문 앞에서 멈추는 연구소 경비원이고, ??는 그다음에 예보 대기 중 팻말을 내미는 안내원입니다. 둘은 붙어 있어도 맡은 일은 다릅니다.

널 병합

?? 왼쪽 값이 null 또는 undefined일 때만 오른쪽 기본값을 고르는 문법.

?.가 모든 오류를 막는 것은 아닙니다. ??도 0, false, 빈 문자열까지 없는 값으로 바꾸지는 않습니다.

교안에는 구조 분해 할당, 스프레드 ..., async·await도 함께 등장합니다. 지금은 “값을 꺼낸다”, “값을 펼친다”, “기다리는 코드를 읽기 쉽게 쓴다” 정도로만 알아보면 충분합니다.

Vite: 만드는 중 확인과 배포 파일 생성을 나눈다

# 만드는 중 브라우저에서 확인
npm run dev

# 배포용 파일 생성
npm run build

npm run build의 기본 결과는 dist 폴더입니다. dist는 배포용 파일을 담은 출고 박스일 뿐, 인터넷에 자동 공개되지는 않습니다. 그 파일을 GitHub Pages 같은 호스팅 서비스에 올려야 다른 사람이 열 수 있습니다.

상세 설명

아이언 감자 연구소 출동 준비

한 화면에서 세 역할을 이어 봅시다.

Element Plus 부품 선반 → ?.·?? 안전검사대 → Vite 시험 구동·build → dist 출동용 파일 묶음

<script setup>
import { computed, ref } from 'vue'
import { ElMessage } from 'element-plus'

// Step 1: 입력값과 최근 예보 준비
const weatherForm = ref({ city: '' })
const latestForecast = ref(null)

// Step 2: 값이 없어도 화면에 보여줄 문구 정하기
const cityText = computed(
  () => latestForecast.value?.city ?? '예보 대기 중',
)

// Step 3: 버튼을 누르면 새 예보 저장하고 알리기
function saveForecast() {
  // 입력 앞뒤의 공백을 제거
  const city = weatherForm.value.city.trim()

  // 공백을 지운 뒤 도시 이름이 비어 있으면 여기서 종료
  if (!city) {
    ElMessage.warning('도시 이름을 입력해 주세요.')
    return
  }

  latestForecast.value = { city }
  ElMessage.success('예보 저장 완료')
}
</script>

<template>
  <!-- Step 4: 준비된 부품을 상태와 함수에 연결 -->
  <el-input
    v-model="weatherForm.city"
    placeholder="도시 이름"
  />
  <el-button type="primary" @click="saveForecast">
    예보 저장
  </el-button>

  <p>최근 예보: {{ cityText }}</p>
</template>

코드는 다음 순서로 움직입니다.

  1. Step 1 — 값 준비: ref가 입력값과 최근 예보를 보관합니다.
  2. Step 2 — 안전한 표시: 최근 예보가 null이면 ?.가 멈추고, ??가 기본 문구를 고릅니다.
  3. Step 3 — 값 변경: 도시가 비어 있지 않으면 새 객체를 저장하고 ElMessage로 결과를 알립니다.
  4. Step 4 — 화면 연결: Element Plus 입력칸과 버튼을 Vue 상태·함수에 연결합니다.

이 화면을 만드는 동안에는 npm run dev로 확인합니다. 준비가 끝나 npm run build를 실행하면 Vite가 기본 dist 폴더를 만듭니다. 그 뒤 호스팅 서비스에 올려야 실제 공개가 끝납니다.

ESLint와 Prettier도 교안에 등장합니다. ESLint는 코드 규칙을 점검하고, Prettier는 들여쓰기와 줄바꿈 같은 모양을 정리합니다. 이번에는 이름과 역할만 알아봅니다.
