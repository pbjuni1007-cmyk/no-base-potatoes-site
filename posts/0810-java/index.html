오늘 만들 것

감자랜드 예약 화면에서 R-101이 4명으로 신청됐습니다. 이 신청을 바로 기록하기 전에, 프로그램은 인원수가 접수 가능한 값인지 먼저 확인해야 합니다.

전체 예약 기능에서 오늘의 위치
예약 화면에서 R-101 · 4명 입력
→ 오늘: Java가 인원수 검사
→ 이후 수업: 접수하고 DB에 기록

왜 필요한가

회원가입이나 예약 같은 기능은 보통 입력받기 → 규칙 확인 → 기록하기 순서로 움직입니다. 0명이나 음수 인원을 그대로 받아 버리면 잘못된 예약 기록이 생깁니다. 오늘은 이 전체 과정 중 가장 작은 판단 한 조각을 Java로 만듭니다.

오늘 직접 만드는 부분
인원수 4를 기억하기 → 0보다 큰지 확인하기 → "예약 신청 가능" 출력하기

버튼, 네트워크 요청과 데이터베이스 저장까지 한꺼번에 구현하지는 않습니다. 오늘 코드가 나중에 어느 자리에 들어가는지 먼저 보고, 그 한 조각만 정확히 읽습니다.

오늘 수업에서 꼭 가져가야 할 것

예약 인원수 4를 기억하고, 접수 가능한 값인지 판단하는 Java 코드를 읽을 수 있을까?

위에서 본 전체 예약 흐름 가운데, 오늘 직접 만드는 판단 코드는 아래 한 조각입니다.

이 코드는 화면 입력을 실제로 받지 않습니다. 화면에서 4명이 들어왔다고 가정하고 숫자 4를 코드에 직접 적어, 그다음 판단만 연습합니다.

작성한 Java 코드

public class Main {
    public static void main(String[] args) { // 1. 시작
        int partySize = 4;                   // 2. 예약 인원수 기억
        if (partySize > 0) {                 // 3. 접수 가능한 값인지 판단
            System.out.println("예약 신청 가능");
        }
    }
}

콘솔 출력

예약 신청 가능

처음에는 세 표지만 찾으면 됩니다.

  1. main — 시작: 이 짧은 콘솔 예제의 실행이 시작되는 이름입니다.
  2. int partySize = 4; — 값 기억: 예약 인원수 4를 partySize라는 이름으로 기억합니다.
  3. if (partySize > 0) — 조건 판단: 인원수가 0보다 클 때만 접수 가능 문장을 출력합니다.

public static void, String[] args는 이 예제를 표준 형태로 시작하는 선언의 일부입니다. 오늘은 긴 선언을 단어별로 외우지 않습니다.

상세 설명

1. main: 이 예제의 시작 지점 찾기

위쪽은 사람이 작성한 소스 코드이고, 예약 신청 가능은 실행 뒤 콘솔에 나온 결과입니다. 둘은 서로 다른 영역입니다.

이 콘솔 예제를 실행하면 JVM이 표준 형태의 main을 호출합니다. 긴 첫 줄을 전부 외우려 하지 말고 main이라는 이름부터 찾습니다.

낯선 말 1개눌러서 뜻 보기
JVM

Java로 작성한 코드를 컴퓨터에서 실행해 주는 프로그램.

모든 Java 프로그램을 사람이 언제나 main부터 직접 실행하는 것은 아닙니다. 지금 설명은 수업에서 다루는 짧은 콘솔 예제에 적용합니다.

2. int partySize = 4;: 검사할 값에 이름 붙이기

  • int: 정수를 다루겠다는 자료형
  • partySize: 예약 인원수를 다시 부를 변수 이름
  • 4: 화면에서 들어왔다고 가정해 코드에 직접 적은 처음 값

이름이 없으면 다음 줄에서 “어떤 4”를 검사하는지 알기 어렵습니다. partySize라고 이름 붙이면 이후 코드도 예약 인원수를 다룬다는 뜻이 드러납니다.

자료형도 이유가 있습니다. 예약 인원수는 숫자이므로 크기를 비교할 수 있어야 합니다. int는 Java가 이 값을 정수로 다루게 하고, 숫자에 맞지 않는 사용을 코드를 실행하기 전에 발견하도록 돕습니다.

3. if (partySize > 0): 규칙으로 다음 행동 고르기

partySize는 4이고, 4 > 0은 참입니다. 따라서 중괄호 안의 출력문이 실행되어 콘솔에 예약 신청 가능이 나타납니다.

실제 예약 서비스라면 최대 정원, 날짜, 중복 신청처럼 더 많은 규칙을 확인할 수 있습니다. 이 예제의 partySize > 0은 조건문이 행동을 고르는 방식만 보기 위한 가장 작은 규칙입니다.

Day 01의 핵심은 문법 이름을 많이 외우는 것이 아닙니다. 검사할 값을 이름으로 기억하고, 규칙을 확인해 다음 행동을 고르는 흐름을 읽는 것입니다. 회원가입 나이 검사나 주문 수량 검사도 입력값과 규칙은 달라지지만 같은 기본 흐름을 사용할 수 있습니다.

오후 수업 예고: 예약 한 건을 객체로 묶기

지금 코드는 인원수 하나만 다룹니다. 실제 예약 한 건에는 예약 번호, 날짜, 인원수처럼 함께 움직여야 할 값이 여러 개 있습니다. 값을 낱개로 흩어 두지 않고 예약 신청이라는 한 묶음으로 다루기 위해 클래스와 객체를 사용합니다.

선택 용어 · 클래스(Class) — 모든 예약 신청이 어떤 값과 기능을 가져야 하는지 Java 코드로 정해 둔 틀.

선택 용어 · 객체(Object) — 그 틀에 예약 번호 R-101과 인원수 4처럼 실제 값이 채워진 예약 한 건.

하나의 BookingRequest 클래스에서 값이 다른 객체를 여러 개 만들 수 있습니다. R-101 / 4명과 R-102 / 2명은 같은 필드와 기능의 약속을 따르지만 서로 다른 예약 상태를 가집니다. Day 02에서는 이 객체들을 List에 담아 같은 검사 규칙을 차례로 적용합니다. 클래스는 현실 물건만 표현하는 설계도가 아니며, 객체도 물건을 물리적으로 복제한 것이 아닙니다. 예약처럼 눈에 보이지 않는 업무도 객체로 나타낼 수 있습니다.

더 읽어보기: 작성한 코드는 어떻게 실행될까

Main.java를 저장했다고 곧바로 JVM이 그 글자를 실행하는 것은 아닙니다.

선택 용어 · 컴파일(Compilation) — Java 소스 코드를 실행 전에 검사하고, JVM이 읽어 실행할 형태로 바꾸는 과정.

흐름은 Main.java → javac → Main.class → java 명령과 JVM → main 메서드 순서로 읽을 수 있습니다. javac는 문법과 타입 오류를 확인해 bytecode가 담긴 .class 파일을 만들고, java 명령은 JVM을 시작해 실행할 클래스를 불러옵니다. 그 뒤 JVM이 main을 시작 지점으로 호출합니다.

컴파일 성공은 실행 가능한 형태가 만들어졌다는 뜻이지, 프로그램이 끝까지 정상 동작한다는 보장은 아닙니다. 배열 범위를 벗어나거나 파일을 찾지 못하는 문제는 실행 중에야 나타날 수 있습니다. 내부 구조를 전부 외우기보다 “소스 작성 단계”와 “JVM 실행 단계”를 구분해 두면 오류가 언제 생겼는지 찾기 쉬워집니다.
