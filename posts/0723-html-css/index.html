HTML과 CSS

Day 01. 구조가 보이는 회원가입 화면

예정 강의일 · 2026.07.23

오늘 만들 것

감자 클럽 회원가입 부스에 닉네임과 이메일을 적고 가입 버튼을 누를 수 있는 화면을 만듭니다. 좁은 화면에서는 입력칸이 위아래로 쌓이고 넓은 화면에서는 두 입력칸이 한 줄에 놓입니다.

왜 필요한가

HTML만 있으면 입력할 내용과 버튼의 의미는 전달되지만 크기와 간격이 정돈되지 않습니다. CSS만으로는 사용자의 값을 받는 입력 구조를 만들 수 없습니다. 두 언어의 역할을 나눈 뒤 연결해야 읽기 쉽고 화면 너비에도 맞는 Form이 됩니다.

오늘 구현하는 흐름은 다음 한 줄입니다.

HTML Form 구조 → CSS selector → box model → Flexbox → 반응형 화면

회원가입 화면에서는 사용자가 닉네임과 이메일을 입력합니다. HTML은 무엇을 입력하는지 구조와 의미를 정하고 CSS는 그 구조가 화면에 어떻게 보일지 정합니다. 실제 값을 검사하고 서버로 보내는 동작은 다음 JavaScript 수업에서 이어집니다.

상세 설명

1. Form 구조를 먼저 확인한다

입력 기능은 input이 맡고 label과 button은 입력 목적과 제출 동작을 나타냅니다. for와 id가 같은 label과 input이 서로 연결됩니다.

<form class="join-form">
  <div class="join-form__row">
    <div class="form-field">
      <label for="nickname">닉네임</label>
      <input id="nickname" name="nickname" required>
    </div>

    <div class="form-field">
      <label for="email">이메일</label>
      <input id="email" name="email" type="email" required>
    </div>
  </div>

  <button type="submit">감자 클럽 가입</button>
</form>

CSS를 지워도 Form의 내용과 입력 순서는 남아야 합니다. 반대로 CSS에 .form-field를 적는 것만으로는 입력칸이 생기지 않습니다.

사용자가 nickname에 눈송이감자를 적으면 name은 nickname, value는 눈송이감자가 됩니다. required와 type="email"은 브라우저의 기본 입력 검사를 돕지만 서버 검증과 보안을 대신하지는 않습니다. 이 코드만으로 실제 계정이나 저장 데이터가 생기지도 않습니다.

2. selector로 HTML element를 고른다

이제 같은 class 이름을 이용해 Form과 입력 묶음을 고릅니다.

.join-form,
.form-field {
  display: flex;
  flex-direction: column;
}

.join-form은 전체 Form을, .form-field는 label과 input을 묶은 각 영역을 고릅니다. 쉼표로 나눈 두 selector가 같은 declaration을 사용합니다. CSS rule이 겹치면 cascade가 어떤 값을 적용할지 정합니다.

3. box model로 크기와 간격을 정한다

* {
  box-sizing: border-box;
}

.join-form {
  width: 100%;
  max-width: 640px;
  padding: 24px;
  border: 3px solid #222;
  margin: 32px auto;
}

.form-field {
  gap: 8px;
}

padding은 Form 내용과 테두리 사이를 벌리고 border는 경계를 그리며 margin은 Form 바깥 공간을 둡니다. box-sizing: border-box를 적용했으므로 선언한 width 안에 padding과 border가 포함됩니다.

4. Flexbox로 입력 묶음을 배치한다

.join-form {
  display: flex;
  flex-direction: column;
  gap: 1rem;
}

.join-form__row {
  display: flex;
  flex-direction: column;
  gap: 1rem;
}

join-form과 join-form__row가 각각 flex container가 됩니다. 좁은 화면에서는 flex-direction: column이 바로 아래 flex item을 위아래로 쌓습니다. gap은 item 사이의 간격을 정합니다.

5. 화면 너비에 맞춰 배치를 바꾼다

responsive web design은 기기마다 별도 HTML을 만드는 일이 아닙니다. 같은 내용을 화면 너비에 맞게 읽고 조작할 수 있도록 CSS layout을 조정하는 방식입니다.

낯선 말 3개눌러서 뜻 보기
viewport

브라우저에서 웹 페이지가 실제로 보이는 화면 영역.

responsive web design

다양한 화면 크기에서도 내용과 조작이 잘 보이도록 화면을 설계하는 방식.

media query·breakpoint

화면 같은 조건에 따라 CSS를 적용하는 규칙과 layout 변경을 시작하는 기준점.

@media (min-width: 640px) {
  .join-form__row {
    flex-direction: row;
  }

  .form-field {
    flex: 1;
  }
}

640px은 이 예제의 breakpoint일 뿐, 모든 화면에 통하는 정답은 아닙니다.

Grid와 Flexbox

Grid는 행과 열을 함께 정해 여러 칸의 위치를 맞추는 CSS layout입니다. 예를 들어 회원가입 페이지의 “소개 / 입력 Form / 도움말”처럼 2차원 영역을 잡는 데 어울립니다. 그 안의 버튼 두 개를 한 줄에 나란히 놓는 일은 Flexbox가 더 단순할 수 있습니다. 둘은 경쟁 제품이 아니라, 바깥은 Grid이고 안쪽 한 줄은 Flexbox인 식으로 함께 쓸 수 있습니다.

position과 z-index

position은 element를 원래 배치 흐름에 두거나, 기준이 되는 조상·화면을 따라 옮길 방법을 정합니다. z-index는 겹치는 element의 쌓임 순서를 조절하지만 숫자가 크다고 언제나 페이지의 모든 것보다 앞으로 오는 것은 아닙니다. position만 썼다고 항상 stacking context가 생기는 것도 아닙니다. 위치가 지정된 element에 z-index가 붙거나, opacity·transform 같은 속성이 적용되면 별도의 쌓임 비교 범위가 생길 수 있습니다. 서로 다른 범위의 숫자는 단순 비교할 수 없습니다.

CSS custom property와 Sass의 SCSS 문법

CSS custom property는 --brand-color처럼 브라우저가 실행 중에도 읽고 바꿀 수 있는 CSS의 값입니다. Sass는 변수와 중첩 같은 기능으로 CSS를 작성한 뒤 빌드 과정에서 일반 CSS로 바꾸는 언어이자 도구이고, SCSS는 Sass가 지원하는 CSS 호환 문법입니다. 둘 다 반복을 줄일 수 있지만, custom property는 브라우저에 남는 실행 시점 값이고 Sass는 배포 전에 CSS를 만드는 도구라는 차이가 있습니다. 이번 회원가입 필수 흐름에서는 이름과 경계만 알아두고 구현하지 않습니다.
