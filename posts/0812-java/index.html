지난 수업 복습

Day 02에서는 예약 R-101을 Java 객체로 다뤘습니다. 객체는 JVM 안에서 값과 동작을 묶어 사용하는 대상이었습니다.

낯선 말 1개눌러서 뜻 보기
Java 객체

JVM 메모리 안에서 클래스에 따라 만들어 프로그램이 다루는 값.

오늘은 그 예약을 웹에서 접수합니다. Java 객체가 인터넷을 그대로 날아가는 것은 아닙니다. 클라이언트는 JSON을 보내고, 서버의 Controller가 그 표현을 Java 객체로 바꿔 받습니다.

POST /reservations 요청은 Controller → Service → Repository를 어떻게 지나갈까?

감자랜드 온라인 예약 접수로 같은 R-101을 이어 봅니다.

POST /reservations HTTP/1.1

URI

서버가 다루는 자원을 구별하는 식별자이며, 여기서는 /reservations가 예약 자원을 가리킨다.

요청 본문

HTTP 요청에서 서버에 전달할 실제 데이터를 담는 부분.

JSON

필수 이동은 세 단계입니다.

  1. Controller — 접수: HTTP 요청을 받고, Spring MVC가 JSON을 Java 객체에 바인딩하면 그 객체를 Service에 넘깁니다.
  2. Service — 업무 규칙: 예약 가능한지 판단하고 저장할 예약 객체를 만듭니다.
  3. Repository — 보관: 예약 객체를 저장소에 넣고 저장 결과를 돌려줍니다.

응답은 Repository → Service → Controller → 클라이언트 방향으로 돌아옵니다.

상세 설명

1. REST는 자원과 행동을 나눠 읽는다

낯선 말 1개눌러서 뜻 보기
REST 자원

웹에서 식별하고 조회·생성·수정·삭제 대상으로 삼는 개념.

/reservations는 예약 하나의 Java 객체나 JSON 문자열이 아닙니다. REST에서 관리할 예약이라는 대상을 가리키는 경로입니다. POST는 그 대상에 새 예약을 생성해 달라는 행동입니다.

같은 예약을 가리켜도 형태는 다릅니다.

  • REST 자원: 웹에서 관리할 reservations라는 대상
  • JSON 표현: 네트워크로 보낸 {"id":"R-101","partySize":4}
  • Java 객체: Controller와 Service가 JVM 안에서 다루는 값

셋은 연결되지만 같은 물건은 아닙니다.

2. Spring MVC가 Controller를 요청 입구로 연결한다

낯선 말 4개눌러서 뜻 보기
프레임워크

애플리케이션의 기본 구조와 실행 흐름을 제공하고 개발자가 필요한 코드를 끼워 넣게 하는 개발 틀.

Spring MVC

HTTP 요청을 알맞은 Controller 메서드에 연결하는 Spring의 웹 처리 구조.

Annotation

@로 시작하며 Spring이 클래스나 메서드의 역할과 연결 정보를 읽도록 붙이는 표기.

바인딩

요청의 JSON 값을 Java 객체의 값으로 연결해 채우는 과정.

아래 코드는 Spring Boot 프로젝트 안에서 연결 관계를 읽기 위한 학습용 코드 조각입니다. import, package, 실행 클래스와 build 설정이 생략되어 있으며, 하나의 Java 파일로 단독 실행되는 예제가 아닙니다.

읽을 두 줄: @RequestBody ReservationRequest request와 reservationService.create(request)

public record ReservationRequest(String id, int partySize) {}

@RestController
@RequestMapping("/reservations")
public class ReservationController {
    private final ReservationService reservationService;

    public ReservationController(ReservationService reservationService) {
        this.reservationService = reservationService;
    }

    @PostMapping
    public ReservationResponse create(
            @RequestBody ReservationRequest request) { // 1. JSON을 Java 객체로 받음
        return reservationService.create(request);     // 2. Service로 전달
    }
}
낯선 말 1개눌러서 뜻 보기
Controller

HTTP 요청을 받고 입력을 해석한 뒤 알맞은 Service에 전달하는 경계.

@RequestMapping("/reservations")와 @PostMapping이 합쳐져 POST /reservations를 create 메서드와 연결합니다. @RequestBody는 JSON 본문을 ReservationRequest로 바인딩합니다.

Annotation은 표지입니다. @PostMapping 자체가 예약 규칙을 판단하거나 데이터를 저장하는 것은 아닙니다.

3. Service와 Repository까지 흐름만 먼저 붙잡기

낯선 말 2개눌러서 뜻 보기
Service

핵심 업무 규칙을 수행하고 필요한 Repository 호출을 조정하는 계층.

Repository

Service가 저장 기술의 세부 내용을 몰라도 저장·조회할 수 있게 경계를 제공하는 계층.

지금은 구현 전체보다 다음 세 줄을 먼저 읽습니다.

POST /reservations + JSON
          ↓
Controller: 요청 접수와 바인딩
          ↓
Service: 예약 규칙 판단
          ↓
Repository: 저장 경계
          ↓
저장 결과가 반대 방향으로 돌아가 HTTP 응답이 됨

객체 생성 패턴과 SOLID는 이런 역할 분리를 설계할 때 도움을 줍니다. Socket은 HTTP보다 아래에서 실제 연결을 제공하고, Spring MVC는 그 HTTP 요청을 Controller까지 연결합니다. 오늘은 각 구현을 외우지 않고 세 계층의 이동만 붙잡습니다.

더 읽어보기: Service 구현

읽을 두 곳: partySize() 조건과 reservationRepository.save(...)

@Service
public class ReservationService {
    private final ReservationRepository reservationRepository;

    public ReservationService(ReservationRepository reservationRepository) {
        this.reservationRepository = reservationRepository;
    }

    public ReservationResponse create(ReservationRequest request) {
        if (request.partySize() < 1) {
            throw new IllegalArgumentException("예약 인원은 1명 이상이어야 합니다.");
        }

        Reservation reservation = new Reservation(
                request.id(), request.partySize(), "CONFIRMED");
        Reservation saved = reservationRepository.save(reservation);

        return new ReservationResponse(
                saved.id(), saved.partySize(), saved.status());
    }
}

Reservation과 ReservationResponse의 타입 선언은 흐름에 집중하도록 이 조각에서 생략했습니다. Controller는 HTTP 접수에 집중하고, “예약 인원은 한 명 이상” 같은 규칙은 Service가 판단합니다.

더 읽어보기: Repository 구현

읽을 두 곳: save라는 약속과 store.put(...)이라는 메모리 구현

public interface ReservationRepository {
    Reservation save(Reservation reservation);
}

@Repository
public class MemoryReservationRepository implements ReservationRepository {
    private final Map<String, Reservation> store = new HashMap<>();

    @Override
    public Reservation save(Reservation reservation) {
        store.put(reservation.id(), reservation);
        return reservation;
    }
}

이 코드는 흐름 학습을 위해 메모리에 보관합니다. 실제 데이터베이스나 JPA에 저장한 것이 아닙니다. Day 05에서 Repository 뒤의 구현을 데이터베이스 저장으로 바꾸는 방법을 배웁니다.
