지난 수업 복습

지난 시간에는 고객·메뉴·주문을 역할별 테이블로 나눴습니다.

고객 번호와 메뉴 번호는 떨어진 장부를 다시 연결할 수 있게 해줍니다. 오늘은 그 장부로 감자 식당 마감 정산표를 만듭니다.

오늘 수업에서 꼭 가져가야 할 것

고객·주문·메뉴로 나뉜 감자 식당 장부에서 필요한 기록을 어떻게 연결하고, 묶고, 순위를 붙일까요?

먼저 LEFT JOIN으로 고객을 남기고 GROUP BY로 고객별 계산을 만든다는 흐름을 붙잡습니다. CTE와 Window Function은 완성된 정산표에서 맡는 역할만 알아봅니다.

JOIN: 떨어진 장부를 연결한다

JOIN은 여러 테이블의 기록을 한 조회 결과에서 함께 보는 문법입니다. 원래 테이블을 하나로 합쳐 저장하는 기능은 아닙니다.

  • INNER JOIN: 양쪽에서 연결되는 기록만 남깁니다.
  • LEFT JOIN: 왼쪽 테이블의 기록은 모두 남깁니다.
  • ON: 어느 기록과 어느 기록을 연결할지 정합니다.

NULL

0이나 빈 글자가 아니라, 값이 없거나 아직 알 수 없다는 표시.

절

SQL 문장 안에서 FROM, JOIN, GROUP BY처럼 한 역할을 맡는 부분.

고객 장부를 왼쪽에 두고 주문 장부를 LEFT JOIN하면, 아직 주문하지 않은 고객도 정산표에 남길 수 있습니다. 붙일 주문이 없으면 주문 쪽 값은 NULL이 됩니다.

INNER JOIN과 LEFT JOIN은 원하는 결과를 쓰는 SQL 문법입니다. Nested Loop, Hash, Merge는 DBMS가 그 결과를 실제로 계산할 때 고르는 JOIN 알고리즘입니다. 이번에는 알고리즘 이름만 알아봅니다.

GROUP BY: 같은 기준의 행을 묶어 계산한다

집계 함수는 여러 행을 하나의 숫자로 요약합니다.

  • COUNT: 개수를 셉니다.
  • SUM: 합계를 구합니다.
  • AVG: 평균을 구합니다.
  • GROUP BY: 같은 고객이나 메뉴의 행을 한 그룹으로 묶습니다.

WHERE는 그룹을 만들기 전에 입력 행을 고르고, HAVING은 집계가 끝난 뒤 남길 그룹을 고릅니다.

다음 단계 역할 1 — CTE: 중간 정산표에 이름을 붙인다

CTE는 WITH로 시작합니다. 긴 쿼리 안의 중간 결과에 이름을 붙여 다음 계산에서 다시 읽게 합니다.

감자 식당 마감 정산실에서는 먼저 고객별 합계라는 중간 정산표를 만든 뒤 최종 정산표에서 다시 읽는 과정과 같습니다. 이 SQL 문장 안에서만 쓰는 임시 이름이지, 새 테이블을 영구 저장하거나 언제나 더 빠르게 만드는 기능은 아닙니다.

다음 단계 역할 2 — Window Function: 정산 행을 유지한 채 순위를 붙인다

이 예시의 GROUP BY는 주문 영수증 여러 장을 고객별 정산 행 하나로 압축합니다. Window Function은 정산 행 수를 그대로 둔 채 옆에 순위 스티커를 붙입니다. 한쪽은 줄이고, 한쪽은 옆에 붙입니다. Window Function이 항상 순위만 계산하는 것은 아니지만, 오늘은 RANK만 봅니다.

  • OVER: 계산할 범위와 순서를 정합니다.
  • PARTITION BY: 계산할 행을 여러 그룹으로 나눕니다.
  • ROW_NUMBER: 각 행에 서로 다른 번호를 붙입니다.
  • RANK: 값이 같으면 같은 순위를 주고 다음 순위를 건너뜁니다.

큰 값부터 작은 값 순서로 정렬하는 방식.

상세 설명

감자 식당 마감 정산실

Day 01의 김감자는 감자튀김 두 개로 6,000원을 주문했습니다. 여기에 준호는 5,000원을 주문했고, 해나는 고객 장부에만 있고 아직 주문하지 않았다고 합시다.

아래 SQL은 Day 01에서 만든 potato_shop 스키마와 customers·menu_items·orders 테이블을 이어서 사용합니다. 먼저 Day 02 정산에 필요한 기록만 추가합니다.

INSERT INTO potato_shop.customers (customer_id, name)
VALUES (2, '준호'), (3, '해나');

INSERT INTO potato_shop.menu_items (menu_id, name, price)
VALUES (11, '감자전', 5000);

INSERT INTO potato_shop.orders
  (order_id, customer_id, menu_id, quantity)
VALUES (1002, 2, 11, 1);

별칭

긴 테이블명이나 계산 결과에 잠시 붙이는 짧은 이름.

COALESCE

앞에서부터 확인해 NULL이 아닌 첫 번째 값을 돌려주는 함수.

-- Step 1: 중간 정산표에 이름 붙이기
WITH customer_totals AS (
  -- Step 2: 고객별 계산 고르기
  SELECT
    c.name AS customer_name,
    COUNT(o.order_id) AS order_count,
    COALESCE(SUM(o.quantity * m.price), 0) AS total_spent

  -- Step 3: 모든 고객을 기준 장부로 세우기
  FROM potato_shop.customers AS c

  -- Step 4: 주문과 메뉴 장부 연결하기
  LEFT JOIN potato_shop.orders AS o
    ON o.customer_id = c.customer_id
  LEFT JOIN potato_shop.menu_items AS m
    ON m.menu_id = o.menu_id

  -- Step 5: 고객별로 묶어 정산하기
  GROUP BY c.customer_id, c.name
)

-- Step 6: 정산 행을 유지한 채 순위 붙이기
SELECT
  customer_name,
  order_count,
  total_spent,
  RANK() OVER (ORDER BY total_spent DESC) AS sales_rank
FROM customer_totals
ORDER BY sales_rank, customer_name;

코드는 다음 순서로 움직입니다.

  1. Step 1 — 이름 붙이기: WITH가 중간 정산표를 customer_totals라고 부릅니다.
  2. Step 2 — 계산 고르기: 주문 수와 총 결제액을 계산합니다.
  3. Step 3 — 기준 세우기: 고객 장부에서 시작합니다.
  4. Step 4 — 장부 연결하기: 고객 번호와 메뉴 번호가 맞는 기록을 붙입니다.
  5. Step 5 — 고객별 정산하기: GROUP BY가 고객마다 결과 행 하나를 만듭니다.
  6. Step 6 — 순위 붙이기: RANK가 정산 행을 유지한 채 매출 순위를 붙입니다.
  • 김감자: 주문 1건 · 총 6,000원 · 1위
  • 준호: 주문 1건 · 총 5,000원 · 2위
  • 해나: 주문 0건 · 총 0원 · 3위

해나가 남는 이유는 customers에서 시작한 LEFT JOIN이기 때문입니다. COUNT(o.order_id)는 해나의 NULL을 세지 않고, COALESCE는 합계를 0으로 바꿉니다.

LEFT JOIN을 INNER JOIN으로 바꾸면 연결할 주문이 없는 해나는 결과에서 사라집니다.

마감 정산실의 고객 명단을 보면 김감자·준호·해나는 모두 최종 정산표에 남고, 주문이 없는 해나만 주문 칸이 비어 있습니다. 해나는 주문을 안 했지, 존재하지 않는 건 아닙니다. 여기서 LEFT는 ‘더 중요한 테이블’이 아니라 SQL에서 실제로 왼쪽에 둔 입력을 뜻합니다.

수업에서 보이면 역할만 알아보기

  • 서브쿼리: 다른 SQL 안에서 결과를 만드는 SQL
  • View: 자주 쓰는 SELECT에 이름을 붙여 테이블처럼 조회하는 정의
  • Materialized View: 조회 결과를 실제로 저장해 두고 필요할 때 다시 갱신하는 구조
  • 집합 연산자: 여러 조회 결과의 행을 합치거나 비교하는 문법
  • 다른 JOIN 종류: RIGHT, FULL, SELF, CROSS JOIN
  • JOIN 알고리즘: Nested Loop, Hash, Merge Join

JOIN은 주로 테이블의 열을 옆으로 연결합니다. 집합 연산자는 여러 조회 결과의 행을 이어 붙이거나 비교한다는 차이가 있습니다.

스스로 확인

Q1 · 정산 결과 읽기

김감자는 6,000원, 준호는 5,000원을 주문했고 해나는 고객 장부에만 있습니다. 아래 쿼리 결과로 맞는 것은 무엇일까요?

SELECT
  c.name AS customer_name,
  COUNT(o.order_id) AS order_count,
  COALESCE(SUM(o.quantity * m.price), 0) AS total_spent
FROM potato_shop.customers AS c
LEFT JOIN potato_shop.orders AS o
  ON o.customer_id = c.customer_id
LEFT JOIN potato_shop.menu_items AS m
  ON m.menu_id = o.menu_id
GROUP BY c.customer_id, c.name;
결과 설명 하나를 고르세요.

Q2 · 정산 행 따라가기

customer_totals에 고객별 정산 행이 세 개 있습니다. 아래 SELECT 뒤 결과는 어떻게 될까요?

WITH customer_totals(customer_name, total_spent) AS (
  VALUES
    ('김감자', 6000),
    ('준호', 5000),
    ('해나', 0)
)
SELECT
  customer_name,
  total_spent,
  RANK() OVER (ORDER BY total_spent DESC) AS sales_rank
FROM customer_totals;
