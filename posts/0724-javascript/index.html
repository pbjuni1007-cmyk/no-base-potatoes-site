Day 02. 입력값이 동작과 요청으로 이어지는 흐름

예정 강의일 · 2026.07.24

오늘 만들 것

감자 클럽 회원가입 부스에서 감자 클럽 가입 버튼을 누르면 JavaScript가 연습용 닉네임과 이메일을 읽어 검사하고 서버 요청 모양으로 바꿉니다. 서버 응답이 오면 화면의 안내 문구도 바꿉니다.

이 코드는 흐름을 배우기 위한 예시입니다. 눈송이감자와 snow-potato@example.test처럼 가상 값만 사용하며 실제 이메일·비밀번호·전화번호를 받지 않고 계정이나 개인정보를 저장하는 서버도 연결하지 않습니다. 예제 값을 넣어 버튼 → 값 → 요청 → 응답 → 화면이 이어지는 순서만 살펴봅니다.

왜 필요한가

HTML Form에는 브라우저의 기본 제출이 있지만 원하는 검사·요청·안내 흐름은 아직 없습니다. JavaScript가 사용자 행동을 듣고 값을 처리해야 화면이 실제 동작으로 이어집니다. 이 흐름을 알면 코드 한 줄씩 외우기보다 입력값이 지금 어디에 있고 다음에 어디로 가는지 찾을 수 있습니다.

지난 수업 복습

Day 01에서는 <form class="join-form"> 안에 nickname, email 입력칸과 감자 클럽 가입 버튼을 만들었습니다. .join-form__row와 .form-field는 각 입력 줄의 CSS 배치를 유지합니다. 오늘은 JavaScript로 그 화면을 새로 만들지 않습니다. 브라우저가 현재 들고 있는 Form을 찾고 제출 행동이 일어날 때 실행할 함수를 연결합니다. 결과를 글자로 알려 줄 #signup-message 영역만 Day 02에서 추가합니다.

document.querySelector()는 Day 01에서 본 CSS selector를 사용해 DOM 요소 하나를 찾습니다. addEventListener("submit", 처리 함수)는 Form의 submit event와 처리할 함수를 연결합니다. inline onclick 대신 화면 구조와 처리 코드를 나누어 읽을 수 있는 이 방식을 사용합니다.

오늘 수업에서 꼭 가져가야 할 것

사용자가 가입 버튼을 누른 뒤 입력값은 어떻게 화면 반응과 서버 요청으로 이어질까?

핵심은 제출을 듣고 → 기본 제출을 막고 → 값을 읽어 검사하고 → 요청을 보내고 → 응답에 따라 DOM 안내를 바꾼다는 흐름입니다.

상세 설명

1. Day 01 HTML에 결과 영역과 JavaScript를 연결한다

Day 01 Form의 닫는 </form> 바로 뒤에 결과 문구와 JavaScript 파일 연결을 추가합니다.

<p id="signup-message" aria-live="polite"></p>
<script src="./signup.js" defer></script>

defer가 있으므로 HTML 분석이 끝난 뒤 signup.js가 실행됩니다. 따라서 아래 코드가 이미 만들어진 Form과 입력칸을 찾을 수 있습니다. aria-live="polite"는 결과 문구가 바뀌었음을 보조 기술이 알 수 있게 돕습니다.

2. 학습용 요청 코드의 순서를 읽는다

아래 코드는 .join-form, #nickname, #email, #signup-message를 사용합니다. /examples/club-signup-preview는 서버와 약속할 주소의 모양을 보여 주는 가짜 endpoint입니다. 이 저장소에는 해당 서버가 없으므로 그대로 복사해 성공 화면을 실행하는 코드가 아니라 요청 순서를 읽는 예시입니다. 실제 서비스에서는 서버도 입력, 인증, 권한과 보안 규칙을 다시 확인해야 합니다.

const form = document.querySelector(".join-form");
const message = document.querySelector("#signup-message");

function isValidApplication(application) {
  return (
    application.nickname.length >= 2 &&
    application.email.endsWith("@example.test")
  );
}

form.addEventListener("submit", async (event) => {
  // Step 1 — 기본 제출 막기
  event.preventDefault();

  // Step 2 — 입력값 읽기
  const nickname = document.querySelector("#nickname").value.trim();
  const email = document.querySelector("#email").value.trim();

  // Step 3 — object로 묶고 조건·함수로 검사하기
  const application = { nickname, email };

  if (!isValidApplication(application)) {
    message.textContent = "연습용 닉네임과 가상 이메일을 다시 확인하세요.";
    return;
  }

  // Step 4 — JSON request body 만들기
  const requestBody = JSON.stringify(application);

  // Step 5 — POST 요청하기. 네트워크 실패만 이 catch로 처리한다.
  let response;
  try {
    response = await fetch("/examples/club-signup-preview", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
      },
      body: requestBody,
    });
  } catch (networkError) {
    message.textContent = "네트워크 연결을 확인한 뒤 다시 시도하세요.";
    return;
  }

  // Step 6 — HTTP 상태 확인하기
  if (!response.ok) {
    message.textContent = `서버가 요청을 처리하지 못했습니다. (${response.status})`;
    return;
  }

  // Step 7 — 응답 본문 읽고 DOM 안내 바꾸기
  const result = await response.json();
  message.textContent = `${result.displayName} 님, 연습 접수가 완료되었습니다.`;
});

코드 주석의 Step 1~7은 위 개념 흐름에서 실제 호출 순서를 찾는 표식입니다.

감자 클럽 부스는 이 순서를 기억하는 보조 장면입니다. 부스 직원이 스스로 가입 여부를 판단한다는 뜻은 아닙니다. 실제 판단은 코드의 조건과 서버 규칙이 하며 fetch()를 호출했다는 사실만으로 저장 성공이 보장되지도 않습니다.

스스로 확인

Q1 · 코드 흐름 따라가기

아래 코드가 정상 응답을 받을 때 입력값이 요청과 화면 안내로 이어지는 가장 알맞은 순서는 무엇일까요?

form.addEventListener("submit", async (event) => {
  event.preventDefault();

  const application = {
    nickname: document.querySelector("#nickname").value.trim(),
    email: document.querySelector("#email").value.trim(),
  };

  if (!isValidApplication(application)) return;

  const requestBody = JSON.stringify(application);
  const response = await fetch("/examples/club-signup-preview", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: requestBody,
  });

  if (!response.ok) return;

  const result = await response.json();
  message.textContent = result.displayName + " 님, 연습 접수가 완료되었습니다.";
});
network error가 없는 정상 응답 경로의 주요 순서를 고르세요.

Q2 · 네 역할 연결하기

제출부터 화면 안내까지 각 코드의 역할을 완성해 봅시다.

Form 제출은 가 듣고 object는 가 JSON 문자열로 바꿉니다. 응답은 를 확인한 뒤 읽고 마지막 안내는 에서 바꿉니다.
