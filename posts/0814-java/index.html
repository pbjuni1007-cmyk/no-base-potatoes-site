2. Repository와 EntityManager: 저장 흐름 맡기기

public interface ReservationRepository
        extends JpaRepository<Reservation, String> {
}
낯선 말 3개눌러서 뜻 보기
EntityManager

entity를 persistence context 안에서 조회·저장·삭제하고 상태를 관리하는 JPA API.

persistence context

EntityManager가 관리 중인 entity와 변경을 추적하는 논리적 공간.

flush

persistence context에 쌓인 변경을 데이터베이스와 동기화하는 과정.

Spring Data JPA의 JpaRepository는 자주 쓰는 저장·조회 기능을 제공합니다. 그 아래에서는 JPA의 EntityManager가 entity 상태를 관리합니다. Spring Data JPA가 새 entity로 판정하면 persist, 그렇지 않으면 merge를 사용합니다. 이 예제처럼 직접 넣은 null이 아닌 ID는 기본 판정에서 기존 entity로 볼 수 있어 Persistable 같은 별도 신규 판정 전략이 필요할 수 있습니다.

findById로 조회해 관리 중인 entity의 값을 바꾸면 JPA가 변경을 추적할 수 있습니다. SQL이 코드 한 줄마다 즉시 실행된다고 외우지 마세요. 변경은 flush 때 DB와 동기화되고 transaction의 commit과 함께 확정됩니다.

3. transaction: 여러 변경의 성공·실패 경계 정하기

@Service
public class ReservationService {
    private final ReservationRepository reservationRepository;
    private final ReservationHistoryRepository historyRepository;

    public ReservationService(
            ReservationRepository reservationRepository,
            ReservationHistoryRepository historyRepository
    ) {
        this.reservationRepository = reservationRepository;
        this.historyRepository = historyRepository;
    }

    @Transactional
    public void confirm(String reservationId) {
        Reservation reservation = reservationRepository
                .findById(reservationId)
                .orElseThrow();

        reservation.confirm();
        historyRepository.save(
                new ReservationHistory(reservationId, "CONFIRMED")
        );
    }
}

이 코드는 Spring Boot 프로젝트의 관계를 읽기 위한 조각입니다. import, 다른 entity와 설정이 생략되어 단독 Java 파일로 실행되지는 않습니다.

낯선 말 3개눌러서 뜻 보기
transaction

여러 데이터 작업을 하나의 성공 또는 실패 단위로 묶는 경계.

commit

transaction의 변경을 성공한 결과로 확정하는 일.

rollback

transaction의 변경을 취소해 시작 전 상태로 되돌리는 일.

confirm("R-101")이 정상 종료되면 예약 상태 변경과 이력 저장이 commit 대상이 됩니다. Spring의 기본 설정에서는 메서드 밖으로 RuntimeException이나 Error가 나가면 rollback됩니다. checked exception과 예외를 잡아버린 경우에는 별도 규칙을 확인해야 합니다.

transaction은 두 변경의 경계를 묶지만, 동시에 들어온 두 요청이 같은 좌석을 예약하는 문제까지 자동으로 막지는 않습니다. 그 문제에는 lock, unique constraint나 재시도 같은 별도 설계가 필요할 수 있습니다.

상세 설명

예약 R-101이 저장되는 흐름

  1. Repository가 primary key R-101로 Reservation entity를 조회합니다.
  2. EntityManager는 조회한 entity를 persistence context에서 관리합니다.
  3. reservation.confirm()이 Java 객체의 상태를 바꿉니다.
  4. 이력 entity도 Repository를 통해 저장 대상으로 추가됩니다.
  5. 메서드가 정상 종료되면 flush와 commit을 거쳐 DB row에 결과가 반영됩니다.
  6. 기본 rollback 대상 예외가 밖으로 나가면 두 변경은 함께 취소됩니다.

더 읽어보기: Actuator

낯선 말 4개눌러서 뜻 보기
Actuator

Spring Boot 애플리케이션의 상태와 운영 정보를 확인할 endpoint를 제공하는 기능.

endpoint

특정 기능이나 정보를 요청할 수 있도록 정한 접근 지점.

health

애플리케이션과 연결된 구성 요소가 동작 가능한지 나타내는 상태 정보.

metrics

요청 수, 메모리 사용량처럼 시간에 따라 측정한 수치 정보.

  • /actuator/health: 애플리케이션과 구성 요소의 상태를 확인합니다.
  • /actuator/metrics: 수집된 metric 이름과 값을 진단할 때 사용합니다. 기본 설정에서는 웹에 노출되지 않으며 별도 설정이 필요합니다.

Actuator는 감자랜드 놀이기구의 물리 안전을 검사하는 장치가 아닙니다. 또한 /env처럼 민감한 정보가 섞일 수 있는 endpoint를 전부 외부에 공개해서도 안 됩니다. 필요한 endpoint만 노출하고 접근 권한을 제한해야 합니다.
