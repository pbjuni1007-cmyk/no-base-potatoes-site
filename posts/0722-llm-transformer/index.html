LLM을 맞추고 줄이고 나누는 네 기술

Day 02. RLHF·Scaling Law·Distillation·MoE 역할 비교

예정 강의일 · 2026.07.22

오늘 만들 것

어제 본 감자 우체국 문장 처리실에서 RLHF, Scaling Law, Distillation과 MoE를 한 표로 비교합니다. 네 기술이 각각 답의 행동, 자원 배분, 작은 모델의 학습 신호와 token별 계산 경로 중 무엇을 바꾸는지 봅니다.

왜 필요한가

네 이름을 발전 단계처럼 외우면 역할을 놓치기 쉽습니다. 문제·변경점·보장하지 않는 것을 나누면 새 모델 설명의 과장을 걸러낼 수 있습니다.

전체 흐름과 오늘의 경계

Day 01의 parameter·training·inference와 FFN에서 출발합니다. 오늘의 네 기술은 필수 파이프라인이 아닌 서로 다른 도구입니다. 제품 순위·가격·버전, 커리어와 홍보 사례는 다루지 않습니다.

선호 순위표 같은 우체국 소품은 기억 장치일 뿐, 고정 대응에 추가되는 기술 정의가 아닙니다.

RLHF: 사람의 비교 신호로 행동을 조정한다

alignment는 모델 행동을 의도한 기준에 맞추는 과정입니다. human feedback에는 사람이 쓴 답과 preference ranking이 포함될 수 있습니다.

InstructGPT는 Supervised Fine-Tuning(SFT) → reward model → reinforcement learning 절차를 사용했습니다. 이해하기 좋은 사례지만 모든 현대 post-training의 보편식은 아닙니다.

preference는 평가자와 기준에 따라 달라집니다. 선호가 곧 진실이나 안전은 아닙니다.

Scaling Law: 경험 관계로 자원 배분을 살핀다

Scaling Law는 특정 모델·dataset·loss 범위에서 model size, data size와 training compute에 따른 loss를 관찰한 empirical law, 즉 경험 관계입니다.

compute-optimal allocation은 정해진 compute budget에서 model size와 data 양을 나누는 문제입니다. Chinchilla는 둘을 함께 검토했지만 특정 비율의 영구 공식은 아닙니다.

loss가 내려가도 모든 능력이 같은 폭으로 좋아지지는 않습니다.

Distillation: teacher의 출력 신호로 student를 학습한다

teacher model은 신호를 만들고 student model은 그 신호로 학습합니다. 대표적인 고전 방식은 teacher logit을 temperature와 Softmax로 soft target 확률분포로 바꿔 student가 따라가게 합니다. raw logit과 soft target은 다른 값이며, hard label보다 후보 사이 관계를 더 담습니다.

teacher 답·풀이를 쓰는 response·trace distillation은 soft target 분포를 맞추는 고전 방식과 다릅니다. 둘 다 출력 신호만 쓸 뿐 내부 사고를 복제하지 않으며 성능 향상을 보장하지 않습니다.

낯선 말 1개눌러서 뜻 보기
generalization

보지 않은 입력에도 배운 관계를 적용하는 정도.

MoE: token마다 일부 FFN expert를 고른다

dense model의 FFN은 token마다 같은 parameter 경로를 씁니다. **Mixture of Experts(MoE)**는 여러 expert, 즉 FFN block 중 일부만 고릅니다. router가 점수를 매기고 Top-k routing으로 k개를 선택하는 sparse activation입니다.

완전한 모델 여러 개 중 하나를 고르는 방식은 아닙니다. expert에 수학·법률 같은 전공 이름도 보장되지 않습니다. 전체 parameter와 활성 parameter는 구분해야 합니다.

상세 설명

감자 우체국 운영 회의의 네 안건

같은 기본 모델과 내일은 눈이 와요를 두고 네 질문을 던집니다.

  1. 행동 조정: 사람의 비교 신호를 반영하는 RLHF. preference는 truth가 아니다.
  2. 자원 배분: 규모와 loss 경향을 참고하는 Scaling Law. 모든 능력을 결정하지 않는다.
  3. 작은 모델 학습: teacher의 출력 신호를 쓰는 Distillation. 내부 마음은 복사하지 않는다.
  4. 활성 계산 선택: 일부 FFN expert를 고르는 MoE. expert는 사람의 전공이 아니다.

네 기술은 함께 쓰일 수도 있습니다. RLHF 다음 Scaling Law 다음 Distillation 다음 MoE처럼 진행해야 하는 순서는 없습니다.

선택 설명 · 필요할 때 펼쳐보기

선택 설명 · Distillation 두 갈래와 MoE 운영 문제

여기부터는 네 도구의 역할을 구분한 뒤 펼쳐 보면 됩니다.

  • 대표적인 고전 knowledge distillation은 teacher logit → temperature 조정 → Softmax → soft target 확률분포 순서로 학습 신호를 만듭니다. temperature를 높이면 가장 큰 후보에만 몰렸던 확률이 완만해져 다른 후보와의 상대 관계도 드러납니다. logit은 Softmax 전 점수이므로 soft target과 같은 말이 아닙니다. 보통 teacher보다 작은 student가 이 목표 분포를 따라 배우지만, teacher의 내부 생각이나 모든 능력을 복사하지는 않습니다.
  • response·trace distillation은 teacher가 만든 답·풀이를 student의 training example로 씁니다. teacher가 그럴듯하게 틀린 답이나 잘못된 풀이를 내면 그 오류도 학습 자료에 들어갈 수 있으므로, 생성 자료의 품질과 출처를 따로 검토해야 합니다.
  • MoE에서는 router가 일부 expert로 일을 몰아버리지 않도록 load balancing을 함께 다루기도 합니다. 한두 expert에 token이 몰리면 나머지 계산 자원은 놀고 붐비는 expert는 병목이 될 수 있기 때문입니다. 사용량을 고르게 만든다고 각 expert가 의미 있는 전공을 자동으로 갖거나 모델 품질이 보장되는 것은 아닙니다.

선택 용어 · logit — Softmax를 적용하기 전, 각 출력 후보에 대해 모델이 계산한 점수.

선택 용어 · load balancing — token이 일부 expert에만 지나치게 몰리지 않도록 사용량을 조절하는 방법.
