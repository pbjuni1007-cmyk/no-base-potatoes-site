지난 수업 복습

지난 시간에는 아이언 감자 연구소에서 슈트의 감자탄 수를 ref()로 만들었습니다. Vue가 그 값을 추적하고, 값을 사용한 계기판도 새 상태에 맞춰 바꾼다는 것을 봤습니다.

오늘은 같은 연구소의 기상 관제판을 조립합니다. 상태와 함수를 정리하고, 화면을 여러 부품으로 나눠 함께 움직여 봅니다.

Composition API: 관제실의 일을 기능별로 모은다

Composition API는 반응형 상태와 관련 함수를 함께 작성할 수 있는 Vue API 묶음입니다. 이 수업에서는 주로 <script setup> 안에서 사용합니다.

  • ref: 검색어와 선택 도시 같은 원본 상태를 보관합니다.
  • computed: 원본 상태를 바탕으로 화면에 필요한 결과를 계산합니다.
  • watch: 지정한 상태가 바뀐 뒤 로그나 요청 같은 별도 행동을 실행합니다.

computed는 의존 값이 바뀔 때 다시 계산합니다. 바뀌지 않았다면 캐시한 결과를 재사용합니다. watch는 새 결과를 만드는 도구라기보다, 변경 뒤에 해야 할 일을 맡습니다.

컴포넌트: 기상 관제판을 작은 부품으로 나눈다

컴포넌트는 화면의 한 역할을 맡는 재사용 부품입니다. Vue에서는 보통 .vue 확장자를 가진 SFC 하나가 부품 하나를 맡습니다.

  • props: 부모가 자식에게 내려보내는 읽기 전용 입력값
  • emits: 자식이 부모에게 보내는 사건 보고
  • 기본 slot: 공통 부품 안에 부모가 내용을 끼워 넣는 자리

연구소 비유에서 props는 내려가는 업무 자료, emits는 올라오는 현장 보고입니다. 하지만 실제로 위아래로 이동하는 것은 아닙니다. 부모가 값을 소유하고 자식이 변경 사건을 알린다는 방향을 기억하기 위한 비유입니다.

상세 설명

아이언 감자 연구소 기상 관제판 조립

연구소의 부모 관제판인 WeatherParent가 검색어와 날씨 목록을 소유합니다. 검색창과 날씨 카드는 필요한 값만 받고, 사용자의 행동은 이벤트로 보고합니다.

아래 한 코드 상자에는 실제로는 네 개의 .vue 파일이 이어져 있습니다. 파일명 주석을 경계로 나눠 읽으면 됩니다.

<!-- BaseDashboardCard.vue -->
<template>
  <!-- Step 6: 부모가 넣은 내용을 공통 카드 안에 표시 -->
  <section class="dashboard-card">
    <slot />
  </section>
</template>

<!-- SearchBar.vue -->
<script setup>
const props = defineProps({ query: String })
const emit = defineEmits(['update-query'])

function updateQuery(event) {
  // Step 3: 검색어 변경을 부모에게 보고
  emit('update-query', event.target.value)
}
</script>

<template>
  <input :value="props.query" @input="updateQuery" />
</template>

<!-- WeatherCard.vue -->
<script setup>
const props = defineProps({ weather: Object })
const emit = defineEmits(['select-card'])
</script>

<template>
  <!-- Step 4: 선택한 날씨를 부모에게 보고 -->
  <button @click="emit('select-card', props.weather)">
    {{ props.weather.city }} · {{ props.weather.temp }}°C
  </button>
</template>

<!-- WeatherParent.vue -->
<script setup>
import { computed, ref, watch } from 'vue'
import BaseDashboardCard from './BaseDashboardCard.vue'
import SearchBar from './SearchBar.vue'
import WeatherCard from './WeatherCard.vue'

// Step 1: 부모가 원본 상태를 소유
const searchQuery = ref('')
const selectedCity = ref(null)
const weatherList = ref([
  { city: '서울', temp: 28 },
  { city: '수원', temp: 27 },
  { city: '부산', temp: 30 },
])

// Step 2: 검색 결과를 자동 계산
const filteredWeatherList = computed(() =>
  weatherList.value.filter((weather) =>
    weather.city.includes(searchQuery.value),
  ),
)

// Step 5: 선택 도시가 바뀐 뒤 행동
watch(selectedCity, (city) => {
  if (city) console.log(`${city.city} 선택 완료`)
})
</script>

<template>
  <BaseDashboardCard>
    <SearchBar
      :query="searchQuery"
      @update-query="searchQuery = $event"
    />

    <WeatherCard
      v-for="weather in filteredWeatherList"
      :key="weather.city"
      :weather="weather"
      @select-card="selectedCity = $event"
    />
  </BaseDashboardCard>
</template>

코드는 다음 순서로 움직입니다.

  1. Step 1 — 상태 소유: 부모가 검색어, 선택 도시와 전체 날씨를 ref로 보관합니다.
  2. Step 2 — 결과 계산: computed가 검색어에 맞는 도시만 골라냅니다.
  3. Step 3 — 검색 보고: 검색창이 update-query 이벤트와 새 검색어를 보냅니다.
  4. Step 4 — 선택 보고: 날씨 카드가 select-card 이벤트와 선택한 날씨를 보냅니다.
  5. Step 5 — 후속 행동: watch가 선택 도시 변경을 확인한 뒤 로그를 남깁니다.
  6. Step 6 — 내용 조립: 기본 slot이 부모가 넣은 검색창과 카드들을 공통 틀 안에 보여줍니다.

reactive, watchEffect, lifecycle hook, provide·inject, named·scoped slot도 교안에 등장합니다. 지금은 “상태·감시·시점·깊은 전달·내용 삽입을 위한 다른 도구도 있다”까지만 알아보면 충분합니다.
