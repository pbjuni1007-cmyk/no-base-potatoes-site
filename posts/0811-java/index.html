Stream API

데이터 소스의 요소를 조건 검사와 변환 같은 연산 흐름으로 처리하는 Java API.

작성한 Java 코드

import java.util.List;

public class Main {
    record RideReservation(String id, boolean confirmed) {}

    public static void main(String[] args) {
        List<RideReservation> reservations = List.of(
                new RideReservation("R-101", true),
                new RideReservation("R-102", false),
                new RideReservation("R-103", true)
        );

        List<String> confirmedIds = reservations.stream()
                .filter(reservation -> reservation.confirmed())
                .map(reservation -> reservation.id())
                .toList();

        System.out.println(confirmedIds);
    }
}

콘솔 출력

[R-101, R-103]

읽을 표지는 세 개입니다.

  1. List<RideReservation> — 타입이 있는 목록: 예약 객체 여러 개를 순서대로 담습니다.
  2. filter — 조건 통과: confirmed()가 true인 예약만 다음 단계로 보냅니다.
  3. map → toList — 번호로 바꿔 모으기: 예약을 ID로 바꾸고 새 결과 목록으로 모읍니다.

상세 설명

1. List<RideReservation>: 목록에 담을 타입 읽기

List.of(...)는 세 예약을 순서대로 담은 목록을 만듭니다. List<RideReservation>의 꺾쇠 안은 이 목록의 요소를 RideReservation 타입으로 다룬다는 컴파일 시점 약속입니다.

제네릭은 잘못된 타입 사용을 컴파일할 때 찾도록 돕습니다. 실행 중에 모든 잘못된 값을 고치거나 예약 내용까지 검증해 주는 기능은 아닙니다.

2. filter → map → toList: 골라서 번호만 모으기

reservations.stream()이 목록의 요소를 처리 흐름으로 보냅니다.

  1. filter(reservation -> reservation.confirmed()): 각 예약의 확정 여부가 참인지 확인합니다.
  2. map(reservation -> reservation.id()): 통과한 예약을 예약 번호로 바꿉니다.
  3. toList(): 번호들을 새 List<String>으로 모읍니다.

R-102는 조건을 통과하지 않아 결과가 [R-101, R-103]이 됩니다. 원본 reservations 목록에서 R-102를 삭제한 것은 아닙니다.

상속

기존 클래스의 멤버를 자식 클래스가 물려받아 재사용하거나 확장하는 관계.

예를 들어 Reservation 인터페이스가 id()와 confirmed()를 약속하고 RideReservation implements Reservation이 이를 구현하면, 목록을 List<Reservation>으로 선언할 수 있습니다. 이때 목록은 객체 내부 구현보다 두 메서드를 호출할 수 있다는 타입 약속에 의존합니다.

클래스 상속은 extends, 인터페이스 구현은 implements로 표시합니다. 둘을 모두 “물려받기”로 뭉개지 말고, 인터페이스에서는 메서드 약속을 구현한다고 읽습니다.

Annotation

컴파일러나 프레임워크 같은 도구가 읽을 수 있도록 코드에 붙이는 구조화된 정보.

Reflection

실행 중에 클래스와 생성자·메서드·필드 정보를 조사하거나 호출하는 Java 기능.

Annotation은 // 주석처럼 사람에게만 남기는 메모와 다릅니다. Annotation 자체가 일을 실행하는 것도 아닙니다. 컴파일러, Spring 같은 프레임워크 또는 직접 작성한 코드가 그 정보를 읽고 의미를 부여합니다.

Reflection은 그런 정보를 실행 중에 찾을 때 쓰일 수 있습니다. 오늘 필수 예제에서는 Reflection으로 객체를 만들거나 private 필드를 바꾸지 않습니다.
