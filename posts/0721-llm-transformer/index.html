Transformer의 다음 토큰 예측

Day 01. 문장이 다음 토큰 확률이 되는 길

예정 강의일 · 2026.07.21

오늘 만들 것

감자 우체국 문장 처리실에 내일은 눈이 와요가 들어왔다고 해 봅시다. 문장을 작은 token으로 나누고 숫자로 바꾼 뒤, Transformer decoder가 앞 token을 참고해 다음 token 후보의 확률을 만드는 길을 따라갑니다.

왜 필요한가

“다음 token을 만든다”는 말 사이의 계산을 알아야 모델 설명을 읽을 수 있습니다.

전체 흐름과 오늘의 경계

필수 흐름은 token·embedding+position → Q/K/V → Q·K → scale → causal mask → Softmax → weighted V → multi-head/output → residual·norm·FFN → 다음 token 확률입니다. 원본 Transformer 전체, NLP 역사와 수식 증명은 미루고 decoder의 causal 흐름에 집중합니다.

오늘 수업에서 꼭 가져가야 할 것

문장이 숫자가 된 뒤, decoder는 무엇을 계산해 다음 token 확률을 만들까?

1. token에 숫자와 위치를 준다

tokenization은 문장을 처리 단위인 token으로 나누는 과정입니다. 내일은 눈이 와요도 모델의 방식에 따라 여러 조각으로 나뉩니다. 감자 우체국에서는 token을 조각 카드로 기억합니다.

각 token은 먼저 embedding이라는 숫자 vector로 바뀝니다. 카드에 붙은 숫자 좌표표가 embedding에 해당합니다. 같은 token이라도 문장 속 순서가 다르면 역할이 달라질 수 있으므로 position 정보도 더합니다.

2. Q·K score를 가린 뒤 V를 섞는다

self-attention은 같은 token열의 정보를 얼마나 섞을지 계산합니다.

  • Query(Q): 현재 위치가 찾을 정보
  • Key(K): 각 위치와 맞춰 볼 정보
  • Value(V): 출력에 실제로 섞을 정보

현재 위치의 Q와 각 위치의 K를 **dot product(내적)**로 비교하고 key dimension의 제곱근으로 나누어 scale합니다. 다음 token을 만드는 decoder는 여기서 아직 나오지 않은 미래 위치의 score에 causal mask를 적용합니다. 그 뒤 Softmax가 남은 score를 합이 1인 attention weight로 바꿉니다. 감자 우체국의 미래 카드 칸막이는 이 순서를 기억하게 합니다. 모델이 미래를 미리 알고 숨긴다는 뜻은 아닙니다.

attention weight는 현재 카드가 다른 카드를 참고하는 비율입니다. 이 비율로 V를 더한 weighted sum이 현재 위치의 새 표현이 됩니다.

Q·K → scale → causal mask → Softmax → attention weight → weighted sum of V 순서입니다. attention weight는 정보를 섞는 비율일 뿐입니다. 진짜 의미, 중요도, 원인, 사실성이나 모델의 설명을 증명하지 않습니다.

3. 여러 head를 합친 뒤 residual·norm·FFN을 거친다

multi-head attention은 masked attention을 여러 head에서 계산합니다. head 결과를 concatenate한 뒤 output projection으로 다음 층이 쓸 크기로 바꿉니다. head마다 사람이 이름 붙인 고정 역할이 있는 것은 아닙니다.

residual connection은 입력을 변환 결과에 더해 정보 경로를 잇습니다. Layer Normalization은 값의 규모를 조정하고 **Feed Forward Network(FFN)**는 각 위치의 표현을 다시 변환합니다.

4. training과 inference는 같은 분포를 다르게 쓴다

decoder 출력은 next-token probability가 됩니다. training은 예측 분포와 target token의 차이인 loss를 줄이도록 parameter를 바꿉니다. attention weight와 target을 직접 비교하는 것은 아닙니다.

inference는 예측 분포에서 다음 token을 고릅니다. 늘 최고 확률만 고르는 것은 아니며 높은 확률이 곧 진실도 아닙니다.

상세 설명

내일은 눈이 와요가 다음 token 후보가 되기까지

감자 우체국 문장 처리실의 실제 기술 흐름을 여덟 단계로 다시 잇습니다.

  1. token·embedding: token을 embedding vector로 바꿉니다.
  2. position: 순서 정보를 더합니다.
  3. Q/K/V: linear transformation으로 Q, K, V를 만듭니다.
  4. masked score: Q·K를 scale하고 causal mask를 적용한 뒤 Softmax를 씁니다.
  5. weighted V: attention weight로 V를 가중합합니다.
  6. multi-head/output: head 결과를 합쳐 output projection을 거칩니다.
  7. residual·norm·FFN: 입력 경로를 잇고 위치별 표현을 변환합니다.
  8. next token: training은 loss를 줄이고 inference는 다음 token을 고릅니다.

여러 decoder layer를 거쳐 token 하나가 붙고, 이를 입력에 더해 계산을 반복합니다.

선택 설명 · 필요할 때 펼쳐보기

선택 설명 · 수업에서 이름을 만날 때

여기부터는 필수 흐름을 확인한 뒤 필요할 때 펼쳐 보면 됩니다.

  • 세어서 표현하기: one-hot, BoW와 TF-IDF는 token의 존재·횟수나 가중치를 희소한 숫자로 표현합니다. N-gram은 연속된 token 묶음을 feature로 만드는 방법이며, 이 묶음의 횟수나 가중치를 vector에 담을 수 있습니다. 어느 쪽도 단어 사이 의미 관계를 스스로 보장하지는 않습니다.
  • 학습한 좌표로 표현하기: Word2Vec 같은 방식은 함께 등장하는 패턴에서 단어 vector를 학습해 가까움을 비교할 수 있게 합니다. 가까운 좌표가 곧 같은 뜻이나 사실이라는 보장은 없습니다.
  • 순서대로 처리하기: RNN, LSTM과 GRU는 앞의 상태를 다음 위치로 넘기며 순서를 다뤘습니다. Transformer는 attention으로 위치 사이 관계를 계산하는 다른 경로를 열었지만, 앞선 방식이 모두 쓸모없어졌다는 뜻은 아닙니다.

원본 Transformer는 입력을 읽는 encoder와 출력을 만드는 decoder를 함께 둔 번역 구조입니다. 지금 배우는 decoder-only LLM은 미래 token을 가린 채 다음 token을 반복 생성합니다. 둘 다 attention을 쓰지만 같은 블록 구성과 학습 목표를 가진다고 외우면 안 됩니다.

선택 용어 · positional encoding — token 순서를 vector에 반영하는 한 방법. 구현 방식은 모델마다 다를 수 있다.

position 정보는 눈이 와요에서 각 token이 몇 번째에 있는지 알려 줍니다. causal mask는 생성 중인 위치가 미래 token을 미리 보지 못하게 막습니다. 둘은 모두 순서와 관련되지만 하나는 위치 정보, 다른 하나는 볼 수 있는 범위의 규칙이라 서로 대신할 수 없습니다.

cosine similarity는 vector 사이 각도, Euclidean distance는 좌표 사이 직선 거리를 봅니다. 어떤 값이 더 알맞은지는 vector를 만든 방식과 검색 목적에 따라 달라집니다. cosine 값이 언제나 0과 1 사이라는 설명도 일반적으로는 틀립니다. 행렬 수식과 구체 구현은 본수업에서 다시 만날 때 펼쳐 봅니다.
