LLM의 답변이 AI 서비스가 되기까지

Day 01. LLM·LangChain과 Basic Agent

예정 강의일 · 2026.09.09

“오늘 몇 시까지 열어요?” 감자랜드 AI 안내데스크에 방문자가 묻습니다. 말을 그럴듯하게 만드는 것과 실제 운영시간을 확인해 알려주는 것은 다릅니다. 오늘은 이 차이를 출발점으로, AI 서비스 안에서 질문과 정보가 어떻게 오가는지 봅니다.

수업에서는 모델을 호출하고 여러 부품을 연결해 기본 Agent를 만듭니다. 여기서는 그 코드를 미리 완성하지 않습니다. 수업에서 나올 이름들이 무엇을 맡고 왜 필요한지 이해하면 됩니다. 아래 운영시간과 방문자 이야기는 설명을 위한 가상 예시입니다.

지난 수업 복습

모델을 학습시킨다는 것은 많은 예시를 바탕으로 내부의 수치를 조정하는 일입니다. 그 내부 수치를 가중치라고 부릅니다. 반면 이미 만들어진 모델에 질문을 주고 답을 받는 일은, 그때마다 모델을 새로 학습시키는 일이 아닙니다.

추론

오늘 수업에서 꼭 가져가야 할 것

LLM이 답하는 것과 AI 서비스가 일을 처리하는 것은 어떻게 다를까요?

LLM은 서비스 안에서 답변을 만드는 부품입니다. 방문자의 질문을 받아 전달하고, 필요한 정보를 조회하고, 다음 질문에 앞선 대화를 붙여 주는 일은 주변 프로그램이 함께 맡습니다. 화면까지 포함한 이 전체 프로그램을 애플리케이션, 줄여서 앱이라고 부릅니다.

감자랜드의 안내데스크 전체가 앱이고, 그 안의 LLM이 답변 생성을 맡는다고 생각해 봅시다. 이 비유에서 LLM이 실제 직원처럼 시설을 둘러보는 것은 아닙니다. 어떤 정보를 전달했고, 무슨 기능을 실행했는지를 따로 확인해야 합니다.

상세 설명

1. 질문을 모델에 보내려면 연결이 필요하다

방문자가 화면에 “오늘 몇 시까지 열어요?”라고 적었습니다. 이 글자가 모델에게 자동으로 전해지는 것은 아닙니다. 앱이 모델을 제공하는 서비스에 질문을 보내고 돌아온 결과를 받아야 합니다.

낯선 말 1개눌러서 뜻 보기
API

프로그램이 다른 프로그램의 기능을 사용하기 위해 정한 호출 방법과 데이터의 약속.

이 예시에서 요청(request)은 앱이 모델 서비스에 보내는 처리 부탁이고, 응답(response)은 그 서비스가 돌려주는 결과입니다. API는 개별 질문 그 자체가 아니라 “어떤 주소와 형식으로 질문을 보내고 결과를 받을지”에 관한 약속입니다.

방문자 → 안내데스크 앱 → 모델 서비스에 요청
방문자 ← 화면에 답 표시 ← 모델 서비스의 응답

수업 코드에서는 이 연결을 돕는 이름들이 한꺼번에 나옵니다.

낯선 말 1개눌러서 뜻 보기
SDK

특정 서비스의 기능을 코드에서 쉽게 부르도록 제공하는 개발 도구 묶음.

낯선 말 1개눌러서 뜻 보기
프레임워크

여러 기능을 연결해 프로그램을 만들 때 사용하는 공통 틀.

옆으로 밀어서 비교 →
이름이 수업에서 맡는 역할
Google GenAI·OpenAI SDK각 제공자의 모델 서비스에 코드로 요청하는 일을 도움
Hugging Face여러 모델과 자료를 찾고 공유하는 플랫폼. transformers라는 라이브러리로 모델을 사용할 수도 있음
LangChain모델 호출·메시지·도구 같은 부품을 연결하는 프레임워크

라이브러리는 프로그램에서 가져다 쓰는 코드 묶음입니다. 이 이름들이 전부 LLM의 이름인 것은 아닙니다. 모델, 모델을 제공하는 서비스, 그것을 부르는 도구, 부품을 잇는 틀이 서로 다른 층에 있습니다. LangChain을 사용해도 실제 답을 생성할 모델은 따로 필요합니다. 또한 제공자를 바꿀 때 지원 기능과 설정까지 모두 같아지는 것은 아닙니다.

수업에서 API 키가 나오면 서비스를 사용할 계정을 확인하는 비밀값이라고 이해하세요. 원고나 공개 코드에 붙여 넣으면 안 됩니다. 교재의 실습 환경인 Colab은 브라우저에서 코드를 실행하는 작업 공간이고, 셀은 글이나 코드를 나누어 적는 칸입니다. 지금 키 발급이나 환경 설치를 해둘 필요는 없습니다.

2. 질문만이 아니라 역할과 형식도 전달한다

“오늘 몇 시까지 열어요?”만으로는 어느 시설인지 알기 어렵습니다. 안내데스크 앱은 자신이 어떤 답을 해야 하는지도 모델에게 알려 줍니다.

낯선 말 1개눌러서 뜻 보기
메시지

대화에서 누가 보낸 내용인지 나타내는 역할과 그 내용을 묶은 단위.

대화형 모델을 수업에서는 Chat Model이라고 부릅니다. 메시지를 입력으로 받아 답변 메시지 등을 돌려주는 모델입니다. LangChain 코드의 메시지 이름은 다음처럼 읽으면 됩니다.

옆으로 밀어서 비교 →
역할안내데스크 예시
SystemMessage앱이 정한 지침: 감자랜드 방문자를 안내하고 확인되지 않은 시간은 추측하지 말 것
HumanMessage방문자 질문: 오늘 몇 시까지 열어요?
AIMessage모델이 생성한 답변 또는 뒤에서 볼 도구 호출 요청
ToolMessage프로그램이 도구를 실행한 뒤 돌려준 결과

같은 문장이라도 사용자 질문인지, 앱의 지침인지, 조회 결과인지 구분할 필요가 있습니다. 역할 표시는 그 구분을 위한 것이지 메시지 내용의 사실성을 보증하는 도장이 아닙니다. 지침을 주었다고 모델이 항상 정확히 따르는 것도 아닙니다.

수업 코드에서 메시지가 여러 개 나란히 있으면 리스트(list), 즉 순서가 있는 목록입니다. 메시지 하나의 역할과 내용처럼 관련 값을 묶어 다루는 단위를 객체(object)라고 합니다. 이름과 값을 짝지은 Python 딕셔너리(dictionary)로 메시지를 표현하기도 합니다. 지금은 객체를 직접 설계하기보다 “한 메시지의 역할과 내용”, “그 메시지들이 순서대로 담긴 목록”을 구분하면 됩니다.

프롬프트

원하는 결과를 얻기 위해 모델에 주는 지시와 질문 등의 입력.

낯선 말 1개눌러서 뜻 보기
프롬프트 템플릿

반복할 입력 문장에 바뀌는 값을 넣을 자리를 마련한 틀.

예를 들어 감자랜드의 {date} 운영시간을 안내해 주세요라는 틀에 2026-09-09를 넣으면 그 날짜의 질문을 만들 수 있습니다. {date}는 여기서 바꿔 넣을 자리입니다. 이런 문자열(string)은 코드에서 글자로 다루는 데이터입니다. 템플릿은 입력을 일정하게 준비해 주지만, 날짜를 채웠다고 그날의 실제 운영시간까지 알게 되는 것은 아닙니다.

이번에는 답을 받은 화면 프로그램의 입장을 봅시다. “열 시부터 여섯 시쯤까지요”보다 시작 시간과 종료 시간이 나뉘어 있으면 각각의 칸에 표시하기 쉽습니다.

낯선 말 1개눌러서 뜻 보기
JSON

이름과 값, 목록 등을 정해진 표기로 적어 프로그램끼리 데이터를 주고받는 형식.

아래는 실행 결과가 아니라 우리가 받고 싶은 가상 응답의 모양입니다.

{
  "date": "2026-09-09",
  "opens_at": "10:00",
  "closes_at": "18:00"
}

closes_at이라는 이름에 18:00이라는 값이 붙어 있으니 앱은 문장의 어느 부분이 종료 시간인지 추측하지 않아도 됩니다. JSON과 Python 딕셔너리는 모양이 비슷해도 같은 것은 아닙니다. JSON은 데이터를 주고받는 표기이고, 딕셔너리는 Python 안에서 이름과 값을 담는 자료 구조입니다.

스키마

데이터에 필요한 항목과 각 값의 종류 등 형식 규칙을 정한 것.

낯선 말 1개눌러서 뜻 보기
구조화 출력

모델의 결과를 미리 정한 데이터 구조에 맞춰 받는 방식.

“날짜, 여는 시간, 닫는 시간이 필요하고 각각 글자 값이어야 한다”가 스키마의 예입니다. LangChain의 Structured Output은 이런 규칙에 맞춘 결과를 받도록 돕습니다. 교재의 Pydantic은 Python에서 데이터의 형식을 선언하고 검사하는 라이브러리입니다. 지금은 클래스 작성법보다 스키마를 코드로 나타내는 역할을 알아두면 됩니다.

여기에도 한계가 있습니다. 닫는 시간에 23:00을 적어도 문자열이라는 형식에는 맞을 수 있습니다. 모양이 맞는가와 실제 운영시간이 맞는가는 다른 질문입니다. 정확한 운영시간을 알려면 다음 장면처럼 근거를 가져와야 합니다.

3. 실제 정보를 가져오는 기능을 연결한다

안내데스크 앱에 날짜를 주면 운영시간 표에서 해당 정보를 찾아주는 기능이 있다고 합시다. 이처럼 필요한 일을 묶어 이름을 붙인 코드가 함수입니다.

낯선 말 1개눌러서 뜻 보기
함수

입력을 받아 정해진 일을 수행하도록 묶어 둔 코드 단위.

함수에 실제로 건네는 값은 인자(argument), 처리 뒤 돌려받는 값은 반환값(return value)입니다. 모든 함수가 같은 입력이나 결과를 갖는 것은 아닙니다. 여기서는 2026-09-09를 건네면 가상의 운영시간 10:00~18:00을 돌려준다고 정하겠습니다.

낯선 말 1개눌러서 뜻 보기
도구

Agent가 사용할 수 있도록 용도와 입력 방법을 알려 둔 프로그램 기능.

함수를 도구로 제공할 때에는 모델이 “언제 쓰고 무엇을 넣을지” 알 수 있도록 이름, 설명, 입력 규칙도 알려 줍니다. 도구 자체가 반드시 AI인 것은 아닙니다. 운영시간 조회처럼 일반 프로그램도 도구가 됩니다.

도구 호출

사용할 도구와 넘길 입력을 지정해 그 기능의 실행을 요청하는 것.

수업의 Tool Calling에서 중요한 구분은 요청과 실행입니다. 모델이 “운영시간 조회 도구에 이 날짜를 넣자”라는 요청을 만들었다고 조회가 끝난 것은 아닙니다. 주변 프로그램이 실제 함수를 실행하고 결과를 돌려줘야 합니다.

  1. 방문자가 오늘 운영시간을 묻습니다. 앱은 오늘 날짜도 입력에 제공합니다.
  2. 모델이 운영시간 조회 도구와 2026-09-09라는 인자를 지정합니다.
  3. 앱이 그 도구를 실행해 가상의 운영시간 표에서 10:00~18:00을 받습니다.
  4. 앱이 조회 결과를 ToolMessage로 모델에게 전달합니다.
  5. 모델이 그 결과를 바탕으로 방문자에게 답할 문장을 만듭니다.

도구가 실제 정보원에 연결되지 않고 고정된 문자열만 반환한다면, 실제 운영시간을 조회한 것은 아닙니다. 위 흐름은 역할을 설명한 것이며 이 글에서 API를 실행한 기록은 아닙니다.

이제 여러 부품을 어떤 순서로 움직일지 정해야 합니다.

낯선 말 1개눌러서 뜻 보기
체인

앞 단계의 결과를 다음 단계에 넘기도록 처리들을 연결한 흐름.

늘 질문 준비 → 모델 호출 → 답 표시 순서로 처리할 수 있다면 그 순서를 미리 정해 연결하면 됩니다. 교재의 LCEL은 LangChain의 처리 부품을 조합하는 표기입니다. 예를 들어 prompt | model | parser는 준비한 입력을 모델에 넘기고 결과를 해석하는 부품으로 잇는 표현입니다. 여기서 parser는 결과를 필요한 형태로 읽는 부품입니다. |를 모든 Python 값에 붙이면 이런 연결이 생긴다는 뜻은 아닙니다.

낯선 말 1개눌러서 뜻 보기
Agent

모델을 이용해 다음 행동을 선택하고 도구의 결과를 보며 처리를 이어가는 프로그램.

방문자가 단순한 인사를 하면 바로 답할 수 있지만, 운영시간을 물으면 조회가 필요할 수 있습니다. Agent는 대화와 도구 설명을 바탕으로 모델이 다음 행동을 선택하도록 구성합니다. 도구 결과가 돌아오면 모델을 다시 부르고, 필요하면 다른 도구를 쓰거나 최종 답을 만듭니다. 교재의 Basic Agent는 이 기본 흐름을 다룹니다.

차이는 “체인은 멍청하고 Agent는 똑똑하다”가 아닙니다. 미리 정한 처리 흐름이 중심인지, 모델이 상황에 맞춰 다음 행동을 선택하는지가 다릅니다. Agent도 무제한으로 움직이는 존재는 아닙니다. 사용할 도구와 멈출 조건은 프로그램이 정해야 합니다.

소개에서 나오는 RAG는 관련 자료를 먼저 찾아 모델 입력에 함께 넣고 답을 생성하는 방식입니다. 운영 안내 문서를 찾아 참고하게 하는 경우를 떠올리면 됩니다. RAG의 초점은 답에 필요한 자료를 공급하는 것이고, Agent의 초점은 다음 행동을 선택하며 처리를 이어가는 것입니다. Agent가 검색 도구로 RAG를 이용할 수도 있지만 두 말이 같은 뜻은 아닙니다. 참고자료가 있어도 잘못 해석하거나 부정확하게 답할 수 있습니다.

4. 이어지는 질문에는 앞선 대화가 필요하다

운영시간을 들은 방문자가 “그럼 마감 한 시간 전에는 몇 시예요?”라고 묻습니다. 이 문장만 받으면 무엇의 마감인지 알기 어렵습니다. 앞의 질문과 18:00이라는 결과가 함께 있으면 “17:00”이라는 답을 만들 근거가 생깁니다.

낯선 말 1개눌러서 뜻 보기
단기 기억

같은 대화 안에서 앞선 상호작용을 이어 쓰기 위해 관리하는 정보.

낯선 말 1개눌러서 뜻 보기
스레드

이어지는 메시지들을 하나의 대화로 묶는 단위.

앱은 앞선 메시지와 결과를 보관하고 다음 모델 호출에 필요한 내용을 넣습니다. 이것이 대화를 기억하는 서비스의 기본 방식입니다. 기록을 저장해 두는 것과 모델 입력에 전달하는 것은 별개입니다. 모델이 저장소의 모든 기록을 자동으로 읽는 것은 아닙니다.

교재의 checkpointer는 대화의 진행 상태를 저장하고 다시 불러오는 장치입니다. thread_id는 어느 대화의 기록인지 구분하는 값입니다. 다른 방문자의 기록을 섞지 않도록 구분해야 하지만, 이 값 하나가 방문자의 본인 인증까지 해주지는 않습니다.

낯선 말 1개눌러서 뜻 보기
문맥

모델이 현재 결과를 만들 때 참고하도록 입력으로 주어진 정보.

낯선 말 1개눌러서 뜻 보기
토큰

모델이 글을 처리할 때 나누어 다루는 조각 단위.

단어 하나가 토큰 하나와 항상 같지는 않습니다. 모델이 한 번에 참고할 수 있는 문맥의 크기에는 한계가 있고, 이를 토큰 수로 나타냅니다. 이 범위를 문맥 창(context window)이라고 합니다. 그래서 긴 대화는 필요한 기록을 고르거나 요약해 전달하기도 합니다.

이 단기 기억은 모델의 가중치를 다시 학습시키는 일이 아닙니다. 또 ‘단기’는 몇 분 후 반드시 지워진다는 뜻이 아니라 같은 대화 안에서 이어 쓰는 범위를 가리킵니다. 프로그램을 껐다 켠 뒤에도 남는지는 저장 방식을 봐야 합니다.
