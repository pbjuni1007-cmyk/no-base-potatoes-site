지난 수업 복습

지난 시간에는 아이언 감자 연구소의 기상 관제판을 여러 컴포넌트로 나눴습니다. 부모가 props로 값을 내려보내고, 자식이 emits로 사건을 보고하는 흐름도 봤습니다.

하지만 연구소에 도시 화면이 여러 개 생기면 부모·자식 관계만으로 모든 문제를 풀기 어렵습니다. 이제 기상 관제판을 외부 기상망에 연결하면서 어느 화면을 보여줄지, 어떤 값을 함께 쓸지, 외부 날씨를 어떻게 받을지를 나눠야 합니다.

오늘 수업에서 꼭 가져가야 할 것

아이언 감자 연구소의 도시 화면, 공통 설정과 서버 날씨는 Router·Pinia·Axios 중 누가 맡을까요?

Vue Router: 주소에 맞는 화면을 고른다

routing은 주소에 따라 보여줄 화면을 고르는 일입니다.

  • route: /weather/seoul처럼 주소와 화면을 연결한 규칙
  • router: route를 보고 화면 이동을 관리하는 도구
  • <RouterLink>: SPA 안에서 다른 주소로 이동하는 링크
  • <RouterView>: 현재 주소에 맞는 컴포넌트가 표시되는 자리
  • params: /weather/:city에서 city 자리에 들어온 실제 값

교안의 RouterVue 표기는 오타입니다. 정확한 컴포넌트 이름은 <RouterView>입니다.

Pinia: 여러 화면의 공통 상태를 관리한다

Pinia는 여러 컴포넌트가 함께 사용하는 상태를 store에 모아 관리하는 Vue 라이브러리입니다.

  • state: 온도 단위처럼 저장한 원본 값
  • getters: state에서 계산한 결과
  • actions: state를 읽거나 바꾸는 동작

Pinia는 데이터베이스가 아닙니다. 새로고침 뒤에도 값을 남기려면 별도의 저장 방식이 필요합니다.

Axios: 서버에 HTTP 요청을 보낸다

HTTP는 브라우저와 서버가 요청(request)과 응답(response)을 주고받는 규칙입니다. API는 다른 프로그램이 정해진 기능이나 데이터를 사용할 수 있게 연 통로이고, Axios는 그 통로로 HTTP 요청을 보내는 JavaScript 라이브러리입니다.

상세 설명

아이언 감자 연구소 외부 기상망 연결

도시 링크를 누르면 Router가 연구소 기상 관제판의 화면을 고릅니다. 화면은 Pinia에서 공통 온도 단위를 읽고, Axios로 해당 도시의 날씨를 요청합니다.

아래는 앱 시작 파일에서 Router와 Pinia 등록을 마쳤다고 가정한 파일별 핵심 코드입니다. 각 코드 상자의 제목이 실제 파일 경로입니다.

router/index.js

import { createRouter, createWebHistory } from 'vue-router'
import CityWeatherView from '../views/CityWeatherView.vue'

export const router = createRouter({
  history: createWebHistory(),
  routes: [
    // Step 1: 주소와 화면 연결
    { path: '/weather/:city', component: CityWeatherView },
  ],
})

stores/settings.js

import { defineStore } from 'pinia'

export const useSettingsStore = defineStore('settings', {
  // Step 2: 여러 화면이 함께 볼 상태
  state: () => ({ unit: 'C' }),
  getters: {
    displayTemperature: (state) => (celsius) =>
      state.unit === 'F'
        ? Math.round((celsius * 9) / 5 + 32)
        : celsius,
  },
  actions: {
    toggleUnit() {
      this.unit = this.unit === 'C' ? 'F' : 'C'
    },
  },
})

App.vue

<script setup>
import { useSettingsStore } from './stores/settings'

const settings = useSettingsStore()
</script>

<template>
  <!-- Step 3: 사용자가 도시 주소와 공통 단위 선택 -->
  <RouterLink to="/weather/seoul">서울</RouterLink>
  <RouterLink to="/weather/busan">부산</RouterLink>
  <button @click="settings.toggleUnit()">
    단위 바꾸기 · °{{ settings.unit }}
  </button>

  <!-- Step 4: 현재 주소의 화면 표시 -->
  <RouterView />
</template>

views/CityWeatherView.vue

<script setup>
import { ref, watch } from 'vue'
import { useRoute } from 'vue-router'
import axios from 'axios'
import { useSettingsStore } from '../stores/settings'

const route = useRoute()
const settings = useSettingsStore()
const weather = ref(null)
const loading = ref(false)
const error = ref('')

async function loadWeather() {
  // Step 5: 주소의 city로 서버에 요청
  loading.value = true
  error.value = ''

  try {
    const response = await axios.get(
      `/api/weather/${route.params.city}`,
    )
    weather.value = response.data
  } catch {
    error.value = '날씨를 불러오지 못했습니다.'
  } finally {
    loading.value = false
  }
}

watch(() => route.params.city, loadWeather, { immediate: true })
</script>

<template>
  <!-- Step 6: 기다림·성공·실패 화면 구분 -->
  <p v-if="loading">날씨 확인 중...</p>
  <p v-else-if="error">{{ error }}</p>
  <p v-else-if="weather">
    {{ weather.city }} ·
    {{ settings.displayTemperature(weather.temp) }}°{{ settings.unit }}
  </p>
</template>

코드는 다음 순서로 움직입니다.

  1. Step 1 — route 등록: 동적 path의 city 값과 도시 화면을 연결합니다.
  2. Step 2 — 공통 설정: Pinia store가 온도 단위를 보관하고, 섭씨 숫자를 선택한 단위에 맞게 계산합니다.
  3. Step 3 — 주소·단위 선택: <RouterLink>를 누르면 URL이 바뀌고, 버튼을 누르면 공통 단위와 온도 숫자가 함께 바뀝니다.
  4. Step 4 — 화면 선택: <RouterView>가 현재 route의 컴포넌트를 보여줍니다.
  5. Step 5 — 날씨 요청: Axios가 params의 도시로 HTTP 요청을 보내고 response data를 저장합니다.
  6. Step 6 — 상태 표시: 요청 중·성공·실패를 나누고, 성공하면 섭씨 기준 응답을 현재 단위에 맞춰 보여줍니다.

이 예시는 세 도구의 역할에 집중하려고 도시를 빠르게 연속 클릭했을 때 이전 요청을 취소하는 처리는 생략했습니다. 실제 서비스에서는 늦게 도착한 옛 응답이 새 화면을 덮지 않도록 요청 취소나 최신 요청 확인이 더 필요합니다.

router.push, lazy loading, catch-all route, defineStore, createPinia, CRUD와 HTTP 메서드 이름도 교안에 등장합니다. 지금은 “이동·설치·데이터 작업을 위한 다음 도구들”이라는 정도만 알아보면 됩니다.
