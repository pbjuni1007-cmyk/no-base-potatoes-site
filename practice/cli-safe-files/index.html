오늘의 미션

nobase-practice/cli-safe-files 안에 폴더와 파일을 만들고, VS Code로 내용을 저장합니다. 그다음 복사·이름 변경·제한된 삭제를 수행하고 ls와 cat으로 결과를 증명합니다.

시작 상태와 안전선

CLI 01을 하지 않았어도 아래 단계로 이 글 전용 폴더를 만들 수 있습니다. 안전 표식(sentinel file) 은 “이 글에서 새로 만든, 버려도 되는 실습 폴더”임을 확인하는 빈 파일입니다. 같은 이름의 경로가 이미 보이면 그 경로를 실습 폴더로 사용하거나 수정하지 않습니다.

mkdir은 폴더를 만드는 명령입니다. -p는 상위 폴더가 없어도 함께 만들고, nobase-practice가 이미 있으면 그대로 두는 옵션입니다. 이번 한 줄에서는 공통 연습 폴더를 준비합니다.

mkdir -p ~/nobase-practice

성공하면 아무 글자도 나타나지 않습니다. 오류가 나오면 다음 명령을 입력하지 말고, 경로 철자와 오류 문장 전체를 확인합니다.

cd는 현재 작업 디렉터리를 바꾸는 명령입니다. 이번 한 줄에서는 공통 연습 폴더로 이동합니다.

cd ~/nobase-practice

성공하면 아무 글자도 나타나지 않습니다. 오류가 나오면 다음 명령을 입력하지 말고, 방금 만든 경로의 철자와 오류 문장을 확인합니다.

ls는 현재 폴더에 있는 이름을 보여 주는 명령입니다. 이번 한 줄에서는 같은 이름의 실습 경로가 이미 있는지 확인합니다.

ls

폴더가 비어 있으면 아무 이름도 나타나지 않을 수 있습니다. 출력에 cli-safe-files가 보이면 여기서 멈추고 다음 명령을 입력하지 않습니다. 기존 경로는 사용하거나 수정하지 말고, 현재 ls 출력을 보존해 어떤 경로인지 확인합니다.

이번 한 줄에서는 이 글 전용 폴더를 새로 만듭니다.

mkdir cli-safe-files

성공하면 아무 글자도 나타나지 않습니다. File exists를 포함한 오류가 나오면 다음 명령을 입력하지 말고, 기존 경로가 생긴 이유를 확인합니다.

이번 한 줄에서는 방금 만든 글 전용 폴더로 이동합니다.

cd cli-safe-files

성공하면 아무 글자도 나타나지 않습니다. 오류가 나오면 다음 명령을 입력하지 말고, 앞 단계의 mkdir 오류 여부와 폴더 이름의 철자를 확인합니다.

touch는 파일이 없을 때 빈 파일을 만드는 명령입니다. 이번 한 줄에서는 글 전용 폴더에 안전 표식을 만듭니다.

touch .nobase-practice-root

성공하면 아무 글자도 나타나지 않습니다. 오류가 나오면 다음 명령을 입력하지 말고, 현재까지 보인 오류와 폴더 이름을 확인합니다.

pwd는 현재 작업 디렉터리의 전체 경로를 보여 주는 명령입니다. 이번 한 줄에서는 올바른 글 전용 폴더에 들어왔는지 확인합니다.

pwd

출력의 끝이 /nobase-practice/cli-safe-files로 나타납니다. 다르면 다음 명령을 입력하지 말고, 출력된 현재 위치와 앞서 입력한 cd를 확인합니다.

ls -la의 -l은 자세한 정보를, -a는 이름이 점(.)으로 시작하는 숨김 파일까지 보여 주는 옵션입니다. 이번 한 줄에서는 안전 표식이 실제로 생겼는지 확인합니다.

ls -la

여러 줄의 목록에 .nobase-practice-root가 나타납니다. 보이지 않거나 오류가 나오면 다음 명령을 입력하지 말고, pwd의 위치와 touch 단계의 오류 여부를 확인합니다.

이후 rm은 이 폴더 안에서 직접 만든 notes/copy-to-delete.txt 한 파일에만 사용합니다. 재귀 삭제, 별표(*), 홈 폴더와 실제 프로젝트는 삭제 대상으로 사용하지 않습니다.

처음 만나는 말

  • 디렉터리(directory): 파일과 다른 디렉터리를 담는 폴더입니다.
  • 파일(file): 이름을 가진 데이터 단위입니다.
  • 편집기(editor): 파일 내용을 작성하고 저장하는 프로그램입니다.
  • 복사(copy): 원본을 남기고 같은 내용을 가진 새 파일을 만듭니다.
  • 이동(move): 파일 위치를 바꿉니다. 같은 폴더에서는 이름 변경으로도 사용합니다.
  • 숨김 파일: 이름이 점(.)으로 시작해 보통의 ls 목록에는 나오지 않는 파일입니다.

3. 복사하고 이름 바꾸기

cp는 첫 번째 경로의 파일을 두 번째 경로로 복사하는 명령입니다. 이번 한 줄에서는 오늘 메모를 today-copy.txt라는 새 파일로 복사합니다.

cp notes/today.txt notes/today-copy.txt

성공하면 아무 글자도 나타나지 않습니다. 오류가 나오면 다음 명령을 입력하지 말고, 원본 경로와 새 파일 이름을 확인합니다.

이번 한 줄에서는 원본과 복사본이 함께 있는지 확인합니다.

ls notes

목록에 today.txt와 today-copy.txt가 함께 나타납니다. 둘 중 하나가 보이지 않으면 다음 명령을 입력하지 말고, 복사 명령의 두 경로를 확인합니다.

mv는 첫 번째 경로의 파일을 두 번째 경로로 이동합니다. 같은 폴더 안에서는 파일 이름을 바꾸는 데 사용할 수 있습니다. 이번 한 줄에서는 복사본 이름을 archive.txt로 바꿉니다.

mv notes/today-copy.txt notes/archive.txt

성공하면 아무 글자도 나타나지 않습니다. 오류가 나오면 다음 명령을 입력하지 말고, 바로 앞의 ls 목록과 두 파일 이름을 확인합니다.

이번 한 줄에서는 이름 변경 결과를 확인합니다.

ls notes

today-copy.txt는 사라지고 today.txt와 archive.txt가 나타납니다. 예상과 다르면 다음 명령을 입력하지 말고, mv에 적은 이전 이름과 새 이름을 확인합니다.

이번 한 줄에서는 이름을 바꾼 파일의 내용을 확인합니다.

cat notes/archive.txt

오늘 메모와 같은 문장이 나타납니다. 다르거나 오류가 나오면 다음 단계로 가지 말고, 파일 이름과 복사 전 원본 내용을 확인합니다.

4. 정해진 복사본 하나만 삭제하기

먼저 삭제 연습에만 쓸 복사본을 만듭니다. 이번 한 줄에서는 archive.txt를 copy-to-delete.txt로 복사합니다.

cp notes/archive.txt notes/copy-to-delete.txt

성공하면 아무 글자도 나타나지 않습니다. 오류가 나오면 삭제 명령으로 넘어가지 말고, 원본과 복사 대상의 경로를 확인합니다.

삭제 전에 위치와 대상을 따로 확인합니다. 이번 한 줄에서는 현재 위치를 확인합니다.

pwd

출력의 끝이 /nobase-practice/cli-safe-files로 나타납니다. 다르면 삭제 명령을 입력하지 말고, 출력된 현재 위치를 확인합니다.

이번 한 줄에서는 현재 폴더에 안전 표식이 있는지 확인합니다.

ls -la

목록에 .nobase-practice-root가 나타납니다. 보이지 않으면 삭제 명령을 입력하지 말고, 현재 위치와 준비 단계를 확인합니다.

이번 한 줄에서는 삭제할 복사본이 정확한 이름으로 있는지 확인합니다.

ls notes/copy-to-delete.txt

notes/copy-to-delete.txt가 한 줄로 나타납니다. 오류가 나오거나 다른 이름이면 삭제 명령을 입력하지 말고, ls notes로 실제 이름을 확인합니다.

rm은 파일을 삭제하는 명령이고, -i는 삭제 전에 확인 질문을 보여 주는 옵션입니다. 이번 한 줄에서는 절대 경로로 지정한 복사본 하나의 삭제를 요청합니다.

rm -i ~/nobase-practice/cli-safe-files/notes/copy-to-delete.txt

Terminal에 이 파일을 지울지 묻는 질문이 나타납니다. 질문 속 경로가 ~/nobase-practice/cli-safe-files/notes/copy-to-delete.txt와 같은 대상을 가리키는지 읽은 뒤에만 y를 입력하고 Return을 누릅니다. 성공하면 그 뒤에는 보통 아무 글자도 나타나지 않습니다. 경로가 다르거나 오류가 나오면 y를 입력하지 말고 멈춥니다.

이번 한 줄에서는 삭제 뒤 남은 메모 파일을 확인합니다.

ls notes

copy-to-delete.txt는 없고 today.txt, archive.txt는 남아 있습니다. 결과가 다르면 추가 삭제 명령을 입력하지 말고 현재 목록을 그대로 확인합니다.

출력에서 확인할 것

  1. cat 출력이 VS Code에서 저장한 문장과 같은가?
  2. cp 뒤에는 원본과 복사본이 함께 있는가?
  3. mv 뒤에는 이전 이름이 사라지고 새 이름이 생겼는가?
  4. rm 뒤에도 삭제 대상이 아닌 두 파일은 남아 있는가?

저장한 오늘 메모 한 줄이 나타납니다. 다르거나 오류가 나오면 다음 명령을 입력하지 말고 원본 파일을 확인합니다.

이번 한 줄에서는 이름을 바꾼 복사본의 최종 내용을 확인합니다.

cat notes/archive.txt

오늘 메모와 같은 한 줄이 나타나면 정상 흐름을 완료한 것입니다.

최종 구조는 다음과 같습니다.

cli-safe-files/
├── .nobase-practice-root
├── README.md
└── notes/
    ├── archive.txt
    └── today.txt

대표 실패와 복구

잘못된 파일 이름을 읽어 봅니다. 이번 한 줄에서는 일부러 없는 todays.txt를 읽습니다.

cat notes/todays.txt

No such file or directory가 나타납니다. 새 파일을 만들거나 다른 이름을 추측하지 말고 현재 위치와 실제 이름부터 확인합니다.

이번 한 줄에서는 실패 뒤의 현재 위치를 확인합니다.

pwd

출력의 끝이 /nobase-practice/cli-safe-files로 나타납니다. 다르면 다음 명령을 입력하지 말고, 출력된 경로를 확인합니다.

이번 한 줄에서는 notes 안의 실제 파일 이름을 확인합니다.

ls notes

archive.txt와 today.txt가 나타납니다. today.txt가 보이지 않으면 다음 명령을 입력하지 말고 앞선 파일 생성과 저장 단계를 확인합니다.

이번 한 줄에서는 확인한 정확한 이름으로 오늘 메모를 읽습니다.

cat notes/today.txt

저장한 오늘 메모가 나타나면 복구 확인이 끝났습니다. 오류가 나오면 새 파일을 만들지 말고 현재 목록과 파일 이름을 다시 비교합니다.

완료 확인

명령 실행 전에 notes 안에 보일 파일 이름 두 개와 각 내용이 같은지 다른지를 예측합니다.

이번 한 줄에서는 예측한 두 파일 이름을 확인합니다.

ls notes

archive.txt와 today.txt가 나타납니다. 예상과 다르면 다음 명령을 입력하지 말고, 어느 단계의 결과가 다른지 설명합니다.

이번 한 줄에서는 오늘 메모의 내용을 확인합니다.

cat notes/today.txt

저장한 오늘 메모가 나타납니다. 다르거나 오류가 나오면 다음 명령을 입력하지 말고 원본 파일을 확인합니다.

이번 한 줄에서는 이름을 바꾼 복사본의 내용을 확인합니다.

cat notes/archive.txt

오늘 메모와 같은 문장이 나타납니다. 두 출력이 같다는 것을 직접 설명하면 완료 확인이 끝납니다.

힌트 없는 변형 과제: notes/today.txt를 보존하면서 같은 내용의 notes/tomorrow.txt를 만들고, ls와 cat만으로 두 파일의 존재와 내용을 증명하세요. 삭제 명령은 사용하지 않습니다.

변형 과제 정답 확인하기

  1. 이번 한 줄에서는 오늘 메모를 tomorrow.txt로 복사합니다.

    cp notes/today.txt notes/tomorrow.txt

    성공하면 아무 글자도 나타나지 않습니다. 오류가 나오면 다음 번호의 명령을 입력하지 말고 두 경로의 철자를 확인합니다.

  2. 이번 한 줄에서는 원본과 새 복사본이 함께 있는지 확인합니다.

    ls notes

    today.txt와 tomorrow.txt가 함께 나타납니다. 둘 중 하나가 보이지 않으면 다음 번호의 명령을 입력하지 않습니다.

  3. 이번 한 줄에서는 원본 내용을 확인합니다.

    cat notes/today.txt

    저장한 오늘 메모가 나타납니다. 오류가 나오면 다음 번호의 명령을 입력하지 말고 앞의 파일 목록을 확인합니다.

  4. 이번 한 줄에서는 새 복사본 내용을 확인합니다.

    cat notes/tomorrow.txt

    원본과 같은 문장이 나타나면 변형 과제를 완료한 것입니다.

더 해볼 사람만

man은 macOS에 설치된 명령 설명서를 여는 명령입니다. 이번 한 줄에서는 mkdir 설명서를 엽니다.

man mkdir

mkdir와 옵션 설명이 나타납니다. q를 누르면 Terminal로 돌아옵니다.

이번 한 줄에서는 cp 설명서를 엽니다.

man cp

cp와 옵션 설명이 나타납니다. q를 누르면 Terminal로 돌아옵니다.

이번 한 줄에서는 mv 설명서를 엽니다.

man mv

mv의 설명이 나타납니다. q를 누르면 Terminal로 돌아옵니다.

이번 한 줄에서는 rm 설명서를 엽니다.

man rm

rm의 설명이 나타납니다. q를 누르면 Terminal로 돌아옵니다. 이번 실습에서 사용하지 않은 옵션은 실제 파일에 바로 시험하지 않습니다.
